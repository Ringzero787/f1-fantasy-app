# f1-fantasy-app — Undercut

This repo is **Undercut** (com.undercut.app): the Expo app (`app/`, `src/`), its Cloud Functions (`functions/`), the **Pit Wall** web portal (`web/pitwall`, Cloudflare Pages) and the Pit Wall worker (`workers/pitwall`, a systemd service on the Linux build box, called "forge" in the docs). Track Limits moved to its own repo, `Ringzero787/tracklimits` (`/data/tracklimits`), on 2026-10-02; nothing of it is built, tested or deployed from here.

It runs the AIDLC gates from Ringzero787/aidlc. Records live in `.aidlc/`. CI runs the deterministic gates only; **before merging any PR, run the model review on this machine** with the `aidlc:aidlc-spec`, `aidlc:aidlc-security`, `aidlc:aidlc-quality` and `aidlc:aidlc-ip` subagents against the branch diff, fix what they find, and say in the PR body that it ran (ADR-003). CI no longer asks the privacy question either, so a change that touches accounts, personal data or a store declaration needs that read too. Before building a feature: `aidlc feature check "<name>"`, then `aidlc feature add "UC: <name>"`, branch `feat/F-###-slug`, Conventional Commits. The `aidlc` skill in the plugin has the full flow.

- **Three things here are shared with Track Limits, which has real players and settles against them.** Treat a change to any of them as a cross-app change:
  - `firestore.rules`, `firestore.indexes.json` and `storage.rules`: the Firebase project has one ruleset, and the `tl_*` rules live in this repo. A Track Limits rules change arrives as a PR here.
  - `functions/src/ingestion/` and the season scripts: Undercut is the only writer of `races`, `drivers` and `constructors`, and Track Limits reads them.
  - Firebase Hosting: the site serves both apps, and `public/.well-known/assetlinks.json` must keep the `com.tracklimits.app` entry.
- Registry names are prefixed `UC:`. Older `TL:` entries are history; the open ones were closed as transferred.
- Registry status: `planned`, then `shipped` once it is live (with `shipped_at`, and `version_shipped` when a store build carried it). Put anything in between in `status_note` — merged and not deployed, partly live, blocked on something. Do not set `building` on a feature that will not be finished by the next release: the release run stamps every `building` feature `shipped`, and stamps any feature whose id is in a commit subject since the last tag. Check the registry after a release run.
- Store builds are local, never EAS: Android with gradle on the Linux build box, iOS with xcodebuild on the Mac Mini (the root `eas.json` is legacy). CI proves compilation with `expo export` only. Release notes per version are `release-notes-<v>.md` at the root; AIDLC also writes `.aidlc/releases/`.
- Production changes — Firestore writes, seeding, Moonshot models, repair scripts, rules/indexes/functions/hosting deploys, the portal and worker deploys, Play publishing — go through `aidlc op` (kinds in `.aidlc/aidlc.yaml` under `overrides.ops`), never a bare script: `aidlc op new <kind> -t … -p key=value`, `aidlc op dryrun`, show the user the output, then `aidlc op apply`. Backups and logs land on `/mnt/smb/f1-app/aidlc-ops`, never in this public repo.
- Undercut Moonshot models (`uc-moonshot-model-seed`) are seeded from the latest Track Limits `MODELS_N.md` on `/mnt/smb/share/tracklimits/` (source `ben_model_R##`).
- Never commit `credentials.json`, `*.keystore`, `*.pem`, or `google-services.json` changes with secrets. The root has many untracked scratch files (F-033); do not `git add -A`, and name every path you stage.
- F1, Formula 1, FIA and Grand Prix are trademark watchlist terms: fine in descriptive copy, never in an app, feature, league or pack name.
