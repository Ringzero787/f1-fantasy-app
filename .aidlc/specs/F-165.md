# F-165 — UC: race-weekend entry check for unmapped car numbers

Created: 2026-11-20 · Status: shipped

## Goal
Mexico (F-134, car 50) and Brazil (F-139, car 51) were each held for days because a car number was missing from `DRIVER_NUMBER_TO_ID`, and nobody looked at the entry list before the race. F-152 now tries to resolve an unknown car by its code and surname, and holds the race when that is ambiguous. A number that should be mapped is still a risk, and the map needs a functions deploy.

This check emails the owner during the weekend, while there is still time to map the car and deploy. It runs hourly from cron on the ops box and does nothing outside a race weekend. It reads only public OpenF1 data and git.

## Acceptance criteria
- [ ] The weekend runs from 5 days before the race start to 8 h after it, and is taken from the OpenF1 Race sessions for this year and next. Outside it, a run prints nothing and sends nothing (uc-entry-check.test.js).
- [ ] The cars come from the Race session's list. Before that list is published, they come from the latest session that has started.
- [ ] A car on a Race, Qualifying, Sprint or Sprint Qualifying list whose number is not in the map is an alert (✗). So is a number that a different driver raced at the previous race.
- [ ] On a practice list, both of those are notes (⚠) and never mailed, so FP1 rookie stand-ins (Las Vegas 2026: CRA, BEG, HIR) cause no false alarm. A driver from the last race who is not entered is always a note.
- [ ] The map is DRIVER_NUMBER_TO_ID from `origin/master`. The log says which source was used, and falls back to the checkout's own file. A parse that finds fewer than 15 cars is an error. The test parses the repo's real config.ts.
- [ ] Reports use the Pit Wall check format, so `pitwall-alert.js` (F-140) applies its rules: an alert after 2 runs in a row, a daily reminder, and an all-clear after 2 clean runs. Each meeting keeps its own state, and the failure line names the race.
- [ ] OpenF1's 401 during a live session skips the run. 12 skips in a row, or a run that cannot finish, count as "could not run", which is mailed after 4 such runs. A 404 for a list that is not published yet reads as empty.
- [ ] OpenF1 values are validated: meeting and session keys must be integers. Text is stripped of control characters before it goes into a report. Report files are written under the per-user state directory, not /tmp.

## Targets
- forge, the ops box, only: `scripts/ops/uc-entry-check.js` plus an hourly crontab line, which is an owner step. No change to the app, functions or rules.

## Data
No user data. It reads public OpenF1 session and driver lists, plus this repo's config.ts. Emails carry car numbers, driver codes, team and race names. State in `~/.local/state/undercut/entry-*.json` holds only those failure lines and timestamps.

## Performance budget
n/a. Outside a weekend, it makes two OpenF1 calls an hour.

## Out of scope
- Checking whether F-152's name resolution would succeed for an unmapped car. That needs Firestore, and mapping the number is the fix either way.
- Knowing whether the map on master has been deployed. A cleared alert means "merged", not "deployed".
