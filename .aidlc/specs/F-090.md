# F-090 — UC: the Amazon build survives R8

Created: 2026-10-02 · Status: building · Registered retroactively

## Goal
Undercut (root app). The Amazon Appstore build of 2.4.0 force-closed on launch, before a line of
JavaScript ran, and Amazon rejected the submission for it ("App force closes upon launch", Content
Policy Validation FAILED). R8 was renaming Amazon's in-app purchasing SDK: its "Kiwi" framework
registers its own components by class name and injects them into an activity lifecycle callback, so
once the names changed the lookup returned null during `Application.onCreate`. The purchase library
bundles the SDK but its keep rules cover only its own package.

## Acceptance criteria
- [x] `-keep class com.amazon.** { *; }` and `-keep class dev.hyo.openiap.** { *; }` reach
      `android/app/proguard-rules.pro` on an Amazon build, with the attribute retention the
      reflection needs.
- [x] The rebuilt APK **launches and renders on a real Fire tablet** (verified on GR734L02527302R8),
      and shows LOGIN WITH AMAZON. A release build that compiles proves nothing here: build 43 and
      the first 2.4.0 Amazon build both compiled.
- [x] The rules are scoped to the Amazon build (F-091 follow-up), so the Play AAB keeps the
      minification it shipped 2.4.0 with and does not retain generic signatures and inner-class
      names app-wide.
- [x] `scripts/release/build-uc-apk-amazon.sh` asserts the rules landed in `proguard-rules.pro`
      (F-091 follow-up). The switch is an environment variable read at prebuild; the failure mode of
      getting it wrong is exactly the crash Amazon already rejected.

## Targets
- amazon

## Data
No user data. A build-configuration change: no new permission, no network call, no field read or
written, no store declaration affected.

## Out of scope
- Any change to what the app sells or how a purchase is verified. Receipt verification stays
  server-side in `validatePurchase`.
- The Play and iOS builds' own minification.

## Known gaps
- Keeping all members of `com.amazon.**` leaves the Amazon billing bridge readable on a rooted Fire
  device. Accepted: the grant is decided by the server from the receipt, so reading the client's
  class names buys nothing. `SourceFile`/`LineNumberTable` are deliberately **not** kept, so crash
  traces still need `mapping.txt`.
