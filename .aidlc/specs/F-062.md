# F-062 — UC: Race winners and per-race league leaderboard

Created: 2026-09-18 · Status: planned

## Goal
Undercut (root app). Free for every league. Today the standings only show season totals, so a league that fell behind has nothing to play for each weekend and `raceWins` is always 0. Recording a winner per race gives every league a weekly result, and gives League Pro (head-to-head, recap, awards) the data it needs.

## Acceptance criteria
- [ ] At scoring time the server writes, per league and race, the ranked member points for that race (`leagues/{id}/raceResults/{raceId}`) and increments `raceWins` on the winning member; ties credit every tied member.
- [ ] Re-running scoring for the same race is idempotent: no double increment (unit-tested with a repeated run).
- [ ] A backfill op (`aidlc op`, dry-run first) populates 2026 races from `raceScores` where rosters allow, and documents which races could not be reconstructed.
- [ ] League screen has a per-race selector showing that race's leaderboard, and the season table shows race wins.
- [ ] Clients cannot write `raceResults` or `raceWins` (rules test).

## Targets
- firebase (functions, rules)
- android
- ios

## Data
Derived league results only; no new personal data.

## Performance budget
One extra document write per league per race at scoring; one document read when a race is selected.

## Out of scope
- Head-to-head pairing (F-063).
- Push notification for race winner (follow-up).
