# F-126 — UC: Moonshot counter counts down at lock

Created: 2026-10-25 · Status: implemented, unreleased · Reported from the field by the owner,
2026-10-25: "moonshot starts counting down 3/3 2/3 1/3 after lock down. so people know they just
used one of their shots."

## Goal
Undercut (app only; no server, rules or portal change). A team gets three Moonshots a season
(`config/app.moonshot.tokensPerTeam`), and the app never showed that as a count: the sheets said
"YOU HAVE 2 MOONSHOTS" in prose, and that number dropped the moment a call was confirmed, while the
call could still be cancelled for a full refund. The Team screen now carries a counter —
MOONSHOTS 3/3 — that moves only when a call locks, which is when the shot is actually gone, with a
note on the weekend it moved so the player knows that is what happened.

## Acceptance criteria
- [x] **One rule for "spent", pure and tested** (`tokenSpent`, `tokensLeftOf` in
      `src/simple/grid/moonshot.ts`): a call has spent its token when it is not CANCELLED, not
      VOID, and no longer open — `callOpen` is the existing rule, CONFIRMED with the lock still
      ahead. A call with no lock time known is not counted (the server decides). Never below zero.
      3/3 → 2/3 → 1/3 → 0/3 as three weekends lock, in the tests.
- [x] **The Team screen shows the counter** under the tiles, before this race's Moonshot card:
      🚀 MOONSHOTS {left}/{total}. With an open call: "ONE IN PLAY · COUNTS WHEN SELECTIONS LOCK".
      Right after the lock, until the race settles: "ONE USED THIS WEEKEND". Settled, or no call
      this race: the count alone. At zero: the existing "NO MOONSHOTS LEFT THIS SEASON".
      (`docs/design/grid/verify/F-126-web-team-counter-call-in-play.png` before the lock;
      `F-125-F-126-web-team-locked-market-entry-counter-moved.png` after it, the same demo session
      with the browser clock moved past qualifying.) A VOID call gave its token back, so it is
      neither in play nor used.
- [x] **The sheets agree with it.** The tile sheet's "YOU HAVE n MOONSHOTS" line now takes the
      same count (it was computed in `GridTeamPanel` from the calls; the rule moved to the pure
      helper). The Moonshot sheet's own line comes from the server's menu, which counts a confirmed
      call as spent the moment it exists — that is what stops a second call going out on one token
      — but the two never show different numbers: while a call is open both sheets show the call,
      not the count. The demo fixture's menu keeps the server's rule, since it stands in for it.
- [x] **The words are server-overridable and inside the vocabulary**: three new copy keys
      (`counter`, `counterInPlay`, `counterUsed`) in `MOONSHOT_COPY`, so `config/app.moonshot.copy`
      can change them without a build, covered by the forbidden-terms test like every other key.
- [x] **No server change.** `moonshotTokens.used` and `TOKEN_SPENDING_STATUSES` are untouched; the
      server's count remains the one that gates a new call. Typecheck, lint and 23 Moonshot tests
      pass.

## Targets

## Data
No user data. Computed on the device from the team's own calls, which the app already downloads.

## Performance budget
One filter over at most a handful of calls per minute tick. Bundle +1 KB source.

## Out of scope
- Changing when the server spends the token. Spending at confirm is what makes two confirms on one
  token impossible (F-106); the counter is a display rule over the same documents.
- The coach marks' fourth card ("YOU GET 3.") still shows the season total, not the count left.
- Verified on Expo web in demo mode (both themes), not on a device build; the line uses the same
  primitives as the PIT WALL line above it.
- Shipping: the next store build after 2.6.0.
