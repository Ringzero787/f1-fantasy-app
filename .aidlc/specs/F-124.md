# F-124 — UC: Pit Wall ungated until ratings

Created: 2026-10-14 · Status: planned · Owner 2026-10-14. Reverses the *charge* side of F-068
until the stores have 50+ ratings; the pass, Stripe, IAP and `hasPass()` stay in the code.

## Goal
Undercut Pit Wall (app + portal + rules). Paid frames currently need the `pw` claim. Nobody has
paid, the beta allowlist hides the surface, and charging before ratings exist is the wrong
sequence. Until 50+ store ratings, every signed-in user reads the paid payloads and sees every
frame. Checkout and the locked veil do not show. Turning paid back on is a flag plus a rules
deploy.

## Acceptance criteria
- [ ] **`PITWALL_CONTENT_OPEN`** is `true` in `src/pitwall/gates.ts` and
      `web/pitwall/src/data/access.ts`. One comment in each file points at the other and at this
      spec.
- [ ] **Rules.** `pw_pages`, `pw_entities`, `pw_projections` allow `read` if `isAuthenticated()`;
      `write` stays `false`. Anonymous still denied. `hasPass()` remains defined. Rules tests:
      a signed-in user without a pass reads those collections; a write still fails; anon fails.
- [ ] **App store.** `refresh()` always loads projections for a signed-in user. `projectionFor`
      does not require an active pass. Tests cover the open path.
- [ ] **Portal.** `can()` returns true for every feature while the flag is on. `loadPayload`
      reads `pw_pages` for every signed-in user. `payloadForAccess` does not drop a paid payload
      on a free viewer. `Locked` / `PassCta` therefore never veil. Tests cover `can(NO_PASS, …)`.
- [ ] **Beta list.** While the flag is on, `pitWallSurface` does not hide the row for users
      outside `config/app.pitwall.beta`. Mode `off` and `enabled: false` still hide it.
- [ ] Purchase, Stripe checkout, IAP and grant/revoke paths are unchanged.

## Targets
- android / ios / amazon (app store + surface)
- web (Pit Wall portal)
- firestore.rules

## Data
No new user data. Authenticated users now read projection and page documents they previously
could not. Those documents are model output, not personal data.

## Performance budget
One extra projections read per signed-in refresh that previously skipped it (the document the
pass holders already read).

## Out of scope
- Taking a payment. IAP product creation in the consoles (F-068 leftover).
- Clearing the live beta allowlist (a later `uc-script` op on `setPitWallConfig.js --beta=`).
  The flag already ignores the list.
- Changing ADR-001: when charging resumes, timing-derived frames stay free.

## Operations
- **rules-deploy** for the authenticated reads.
- **pitwall-pages-deploy** for the portal `can()` / payload change.
- App JS OTAs. No store build required for ungating.
- To charge later: set the flag false, restore `allow read: if hasPass()` on the three
  collections, rules-deploy + pitwall-pages-deploy.
