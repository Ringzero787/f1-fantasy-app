# F-076 — TL: repair race schedules from seed data

Created: 2026-09-24 · Status: planned

## Goal

The `races` documents in Firestore had drifted from the bundled seed data: every upcoming round from R18 to R24 carried the **previous** round's weekend in its `qualifying` and `race` fields — a cascading off-by-one. Singapore (R18) was stored as Oct 3–4 when the race is Oct 11, so picks would have locked and settled a week early; USA (R19) was flagged `hasSprint: true` with a stray `schedule.sprint`, which would have rendered a phantom Sprint tab for a non-sprint round. The bundled `_seedRacesData.json` was correct throughout — only the live documents were wrong.

Re-running `tlSeedRaces` is not sufficient, which is why this script exists. That endpoint writes with `{ merge: true }` (`seedRaces.ts:52`), and a merge updates fields but never removes them. The live docs held keys the seed file does not — USA's `sprint`/`sprintQualifying`, Singapore's `fp2`/`fp3` (a sprint weekend runs one practice session). Those would have survived a re-seed, and because the app treats `!!hasSprint || !!schedule.sprint` as a sprint weekend (`app/(tabs)/index.tsx:204`), USA's phantom Sprint tab would have persisted even after `hasSprint` flipped to false.

## Acceptance criteria
- [ ] Every non-completed 2026 race's `schedule` matches `_seedRacesData.json` exactly — same keys, same times.
- [ ] Keys present in Firestore but absent from the seed file are **deleted**, not merely left in place.
- [ ] `hasSprint` matches the seed file, which matches the real 2026 sprint calendar (China, Miami, Canada, Silverstone, Zandvoort, Singapore).
- [ ] No race has any session timestamp later than its own `race` timestamp.
- [ ] Races with `status: completed` are left untouched — their weekends are settled history.
- [ ] The script dry-runs by default and only writes with `--write`, printing every change as `field: old -> new` or `-> DELETE`.
- [ ] The planner is pure and unit-tested without Firestore, including the delete path and the completed-race skip.
- [ ] A test asserts the seed file itself is internally consistent: exactly the six real sprint rounds, no session after its race, sprint rounds carrying `sprint`+`sprintQualifying` and no `fp2`/`fp3`.

## Targets
- android

## Data
No user data. Operator-run repair of the `races` collection (schedule timestamps and the `hasSprint` flag), sourced entirely from data already bundled in the repo.

## Performance budget
n/a — one collection read and a single batched write, run manually.

## Out of scope
- Completed races. Four of them differ from the seed by an hour or two; rewriting settled history buys nothing and risks disturbing already-graded weekends.
- Fixing whatever originally corrupted the documents. The seed file is correct, so the drift came from some other writer; identifying it is separate work.
- The empty `ben_lines/*_sprint` shells for usa/brazil/qatar (0 entities, `posted: false`) — harmless season-setup placeholders. `singapore_2026_sprint` is absent and gets created when its lines are seeded via `tl-lines-seed-sprint`.
- Undercut's `races` handling. This is Track Limits only.
