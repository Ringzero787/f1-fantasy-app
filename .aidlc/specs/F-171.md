# F-171 — UC: race-correction end-to-end test on the Firestore emulator

Created: 2026-11-24 · Status: building

## Goal
F-168 added automatic post-race result corrections (`applyRaceCorrection` in `functions/src/scoring/raceCorrection.ts`). The `onRaceCompleted` trigger calls it, and so does `functions/scripts/correctRaceResults.js`. Its unit tests run on a hand-written fake Firestore. The fake accepted `tx.update(teamRef, { constructor: … })`. The real SDK refuses that write at commit ("Can't merge current value into a nested object", because of `Object.prototype.constructor`). So the bug shipped, and it surfaced only when the production repair op OP-239 ran (fixed in #305 with `set` + `mergeFields`).

This feature runs the correction path against the real Firestore emulator through the real `firebase-admin` SDK. A write shape that the SDK or Firestore refuses now fails a test.

## Acceptance criteria
- [x] `functions/test/emulator/raceCorrection.emu.test.js` seeds a race shaped like Las Vegas 2026: Hadjar's penalty swaps him with Lawson after scoring. The seed has the race doc with the old results and `scoringCompletedAt`, four teams with `raceSnapshots`, a league with `members`, `raceScores` rows, `priceHistory` rows, `config/app` and a settled Moonshot. The teams cover a constructor object, `constructor: null`, a driver Ace and a constructor Ace (both ×2 under the cap), a pick sold since the race (banked into `lockedPoints`), and a team holding neither swapped driver.
- [x] (a) `applyRaceCorrection` with the trigger's real `syncLeaguesForRace` moves each team's `totalPoints` and `lockedPoints` by the spelled-out per-pick delta. It rewrites the snapshot's race phase (keeping `adjustment`, `scoredAt` and the qualifying phase), stamps `resultsSig` with one audit entry, rewrites exactly the 4 moved `raceScores` rows, and moves the best race. It also sets league member totals and `lastRacePoints`, re-ranks the members and rewrites the weekend leaderboard. Prices are not rewound.
- [x] (b) A second run changes no document (idempotent through `resultsSig`). The one exception is the `raceScores` rows' `timestamp` (see Out of scope).
- [x] (c) The dry run reports the same teams and writes nothing (a full database dump before and after is compared).
- [x] (d) A team doc deleted after the team list was read is not recreated, and its snapshot is left alone. The other teams are still corrected.
- [x] (e) The deployed trigger works end to end. `onRaceCompleted` is exported from `functions/lib/index.js` and wrapped with `firebase-functions-test`. A before/after change of `results` produces the same corrected outcome. The trigger logs a correction error instead of throwing it, so the test fails on any `console.error`. A redelivered event is a no-op. No secrets or other config are needed. Only a `storageBucket` is named, because two modules call `admin.storage().bucket()` at load time.
- [x] (f) `repairExpirySale.js` `planTeam` and its transaction write commit for a team with a constructor. The write moved, unchanged, into an exported `writeRepair` helper that `main` uses.
- [x] Proven to catch the bug. With the #305 fix reverted (`tx.update(teamDoc.ref, …)` in `raceCorrection.ts` and in `repairExpirySale.js`), (a), (b), (d), (e) and (f) fail with "Can't merge current value into a nested object". Restored, all 6 pass.
- [x] Runner: `npm --prefix functions run test:emulator` builds, then `firebase emulators:exec --only firestore --project demo-f171`. The `demo-` project keeps it offline. `functions/test/emulator/run.sh` picks a JDK 21+, which firebase-tools 15 requires. The unit run `node --test test/*.test.js` does not match the directory. Without `FIRESTORE_EMULATOR_HOST` the file skips.
- [x] CI. The workflow (`.github/workflows/aidlc-pr.yml`, rendered by `aidlc sync`) installs no firebase-tools and was not touched. Its test command already runs `npm run test:rules` (`scripts/ops/run-rules-tests.sh`), which starts the sha256-pinned emulator jar on the runner's Java. That script now runs `functions/test/emulator/*.emu.test.js` beside `rules-tests/`. The test uses its own `demo-f171` project, so it cannot collide with the rules tests running in parallel. It passes on the pinned v1.19.8 jar under JDK 17 as well as under the CLI.

## Targets

- `firebase.json`: an `emulators` block (firestore 8186, websocket 9156, hub 4406, logging 4506, UI off), off the defaults because other emulators run on the build box.

## Data
Synthetic fixtures only, in a `demo-` emulator project. No production access and no personal data.

## Performance budget
The emulator suite runs in about 3 s after the emulator starts, and adds about 3 s to `npm run test:rules`.

## Out of scope
- Every run of `applyRaceCorrection` with a changed classification rewrites the moved `raceScores` rows with a fresh server timestamp, even when every team was already corrected. The fields are identical, so this is harmless and the test pins the behaviour. It is not changed here.
- A team deleted while a correction runs is not recreated (d), but the league sync still uses the team list read at the start. Its owner stays on that race's weekend leaderboard with the deleted team's race points; their member total is untouched. Edge case, not changed here.
- Isolation: the test always uses project `demo-f171` (never `GCLOUD_PROJECT`), so it cannot clear the rules tests' `demo-uc-rules` data on the runner's CLI fallback path.
- Sprint-weekend and standalone-sprint corrections on the emulator. The unit tests cover the phase routing.
- Testing `correctRaceResults.js` itself. Its `main` needs `SA_KEY` and refuses any project but production. It calls the same `applyRaceCorrection` covered here.
