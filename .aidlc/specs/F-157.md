# F-157 — UC: app reads the current season everywhere (2027-ready build)

Created: 2026-11-17 · Status: building

## Goal

The app still carries the year. Eight places decide behaviour with a quoted `'2026'`: `src/simple/grid/GridLeagueManager.tsx:103`, `src/store/league.store.ts:605`, `app/(tabs)/index.tsx:40`, `app/(tabs)/calendar/index.tsx:19`, `app/(tabs)/calendar/[id].tsx:21`, `app/(tabs)/leagues/create.tsx:30` and `src/simple/grid/showcaseData.ts:74,119` (25 more are demo data). There is a numeric one at `src/admin/AdminContent.tsx:972` and hard-coded year labels in `app/(tabs)/profile.tsx` and `app/(tabs)/market/driver/[id].tsx`. The last-race view (`getLatestRound` in `src/services/raceScores.service.ts`) takes the latest round across all seasons, so in 2027 it would sit on Abu Dhabi 2026. Season-shaped defaults are bundled too: `totalRounds: 25` and the 2026 sprint rounds in `src/services/remoteConfig.service.ts`, `SPRINTS_PER_SEASON: 6` in `src/config/pricing.config.ts` (2027 has ten sprint weekends), `FULL_SEASON_RACES: 23` in `src/config/constants.ts`, the car-number table in `src/services/openf1.service.ts`, and track art that has no entry for the two circuits new in 2027. The server side is already season-aware (F-149, F-151); this is the app half, and it needs a store build on all three stores before the opener.

Source: the 2026-11-17 EGM review of 2027 readiness (finding R-03); the evidence lines were re-checked against `origin/master` on that date. Dates are proposals worked back from the 2027-03-14 opener, not owner decisions, unless marked.

## Acceptance criteria
- [x] No year literal decides behaviour in `src/` or `app/`: the season comes from `config/app.currentSeason`, with a test that fails on a new literal (demo data excepted by path).
  - Met: one rule in `src/utils/season.ts` (mirrors `functions/src/season/current.ts`), read through `useCurrentSeasonId` / `getCurrentSeasonId` in every former literal site; `__tests__/utils/yearLiterals.test.ts` parses every string, number, template and JSX text literal in `src/` and `app/` and fails on a year (demo, fixture, showcase, test paths and the one last-resort constant excepted by path). Also season-blind orderings: the lock's next race (`getNextIncompleteRace`) sorts by season then round, and the Grid profile and team panel no longer take the season of the highest round on file.
- [x] What the app does when `config/app.currentSeason` is absent or unreadable is specified and tested. The document is readable only when signed in, and nothing in the app reads the field today.
  - Met: absent or junk → the season of the most recent started race on the live calendar (the bundled demo calendar never counts) → `LAST_RESORT_SEASON_ID` in `src/utils/season.ts`; `__tests__/utils/season.test.ts` and `__tests__/store/currentSeason.test.ts`.
- [x] The season-shaped defaults listed in the Goal (round count, sprint rounds, sprints per season, full-season race count, car numbers) come from the server or are correct for 2027.
  - Met: `totalRounds`/`sprintRounds` default to unset and are filled from the current season's race documents (`withSeasonShape`), a `config/gameRules` value still wins; `SPRINTS_PER_SEASON`, `LOCK_BONUS.FULL_SEASON_RACES` and `SEASON_LOCK_RACES` were unread and are gone (the server counts them); car numbers resolve from the active `drivers/{id}.number` first, the bundled table is only the fallback for the admin OpenF1 import (`__tests__/services/seasonDefaults.test.ts`).
- [ ] Track art and layouts exist for every circuit on the 2027 calendar.
  - Left: no artwork for Portimão or Istanbul Park (owner item; not drawn from memory). `TrackIcon` now shows a neutral flag for any circuit without art, so no blank tile; `src/data/trackLayouts.ts` is not read by any screen.
- [x] The update links F-116 needs are in this build: the Amazon branch in the update gate and a real iOS store URL. Without them the floor cannot be raised.
  - Met: `src/config/storeLinks.ts` + `AppUpdateGate`: Amazon builds use `config/app.amazonUrl`, then `amzn://`, then the Amazon web listing, never Play; iOS falls back to apps.apple.com/app/id6759428075 (`__tests__/config/storeLinks.test.ts`).
- [x] `raceScores` queries and the last-race view are scoped to the current season.
  - Met: `getLatestRound`, `getPreviousRaceScores` and `getScoresForEntity` take the season; rows without `seasonId` (pre-F-168) are placed by race id. New composite index `raceScores (entityType, seasonId, round desc)` needs an index deploy op before the 2027 opener; until then the unscoped read still serves 2026 (`__tests__/services/raceScoresSeason.test.ts`).
- [x] League creation stamps the current season.
  - Met: `GridLeagueManager`, `leagues/create.tsx` and the demo join read `getCurrentSeasonId()` at create time.
- [ ] Run against a rolled-over copy in the emulator (F-154's, or one made the same way): Team, Market, League, recap and round report show 2027 state, and 2026 history is still reachable where the design keeps it.
  - Left: not run in this pass (no emulator run asked for); needs F-154's rolled-over copy.
- [ ] Released on Play, the App Store and Amazon; the live version per store is recorded.
  - Left: no store build yet.
