# F-046 — UC: Auto-fill log and price hardening

Created: 2026-09-17 · Status: planned

## Goal

Two advisory findings from the CI security gate on F-044 (PR #44). The auto-fill log in `autoLockTeams` put race names and document ids into the first argument of `console.log`, which Node treats as a format template, so a `%s` in a race name could forge a Cloud Logging line. And driver prices were clamped at zero for the knapsack while constructor prices were not, so a zero or negative price on an active constructor document would have credited the bank instead of debiting it. Server only.

## Acceptance criteria
- [ ] The auto-fill success and failure logs in `autoLockTeams` pass document-sourced values as `console.log`/`console.error` arguments, never inside the format string.
- [ ] `loadFillContext` and the stamped roster rows clamp every price at zero after rounding up; `selectValueFill` uses the same clamped constructor price for the affordability check and the cost.
- [ ] A constructor candidate with a negative price never reduces the fill cost below the drivers' cost (node test).
- [ ] `node --test functions/test/autoFill.test.js` passes.
