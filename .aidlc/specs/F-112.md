# F-112 — UC: Security review 2026-10 hardening before the 2.5.0 build

Created: 2026-10-07 · Status: building · Design source: four security audits run on 2026-10-07 over the Moonshot server, the app code in the 2.5.0 build, the Pit Wall portal, and the rules / callables / ops surfaces

## Goal
Undercut (root app). Before the first store build that carries Moonshot, close what the review found. Nothing found was exploitable by a player with a modified client — ownership, pricing authority, idempotency and the rules deny-lists all held — but one failure mode was serious (settlement on an empty classification), several mediums were cheap to close, and a few hygiene items had been noted more than once.

## Acceptance criteria
- [ ] **Settlement needs a classification.** `settleMoonshotsForRace` settles nothing unless the race is cancelled, or `completed` with a non-empty `results.raceResults`; an empty or half-ingested classification with DNS = LOSS would otherwise mark every open call MISSED permanently (test: empty results → no writes).
- [ ] **Confirm reads the token document.** `moonshotConfirm` reads `moonshotTokens/{team}_{season}` inside the transaction before writing it, so two confirms for one team contend on a document both have read (Firestore aborts on a changed read set), not only both write.
- [ ] **Points balance is the ranked total.** Eligibility's POINTS balance is `memberSeasonTotal(team)` (active + banked + Moonshot), so a team in the red from earlier calls cannot keep risking its gross points.
- [ ] **Full-mode repair refuses teams with settled cash Moonshots** (it rebuilds `budget` from `totalSpent` and would refund misses and erase hits); incremental repair still runs.
- [ ] **Bounded quotes.** A quote document is one per (team, race, driver, prediction, target, currency, stake) tuple — a re-quote overwrites — so a script cannot grow `moonshotQuotes` without bound. Confirm still checks `used` and `expiresAt`.
- [ ] **Input hygiene.** Ids capped at 128 chars; model driver lookups are own-property reads (no `constructor`/`__proto__` keys); the live sweep accepts only whole car numbers and positions 1–30 and an integer session key; config clamps `vig` 0–0.5, `minMultiplier` 0.1–2, `maxMultiplier` 1–50, `tokensPerTeam` 1–20, `maxPerRace` 1–5 (test).
- [ ] **Handoff rate limit on the client address.** `pw-redeemPortalHandoff` keys its limit on the first `x-forwarded-for` hop, not Cloud Run's proxy address, so one key is no longer shared by every portal sign-in.
- [ ] **Rules: league content is for approved members.** `raceResults`, `activity`, `invites`, `announcements` (+ replies) and `messages` read with `isApprovedLeagueMember` (owner and, where it was, admin kept); a join awaiting approval reads only the member list. `fantasyTeams` and `notifications` lists are scoped: a team list must be the owner's own or one league's; a notifications list the owner's own. Every shipped client query carries those filters (rules tests replay them). The one that does not — the global team-name query of builds before 2.3.2 (F-059 step A moved it to `checkTeamNameAvailable` on 2026-09-19) — is refused, so `functions/scripts/setAppVersionGate.js` raises `config/app.minVersion` to `2.3.2` (op-script convention, `uc-script` kind) and is applied **before** the rules deploy: a 2.3.1 device sees the update screen, not a failed rename.
- [ ] **App.** The menu is coerced like the call (`toMenu`: arrays default empty, balances to 0, server band labels through the vocabulary check) so a partial answer cannot throw in a render; the tutorial flag is an `updateDoc` (no ghost `users` document); one confirm in flight at a time; a persisted demo session is dropped on hydrate in a build that does not allow demo.
- [ ] **Portal.** The Season tile's record lines never throw on a partial `moonshotStats`.
- [ ] **Repo.** The three unguarded root scratch scripts are removed; `.gitignore` covers `*.p8`, `*.p12`, `*.mobileprovision`, `.env.production`; the PR workflow installs root dependencies with `--ignore-scripts` like the function packages.

## Noted, not changed here (owner decisions or larger work)
- `leagues` is readable by any signed-in user and stores `inviteCode`, so codes can be harvested and approval-free leagues joined uninvited. The join flow in released clients queries by `inviteCode`; moving codes to `leagueCodes/{CODE}` or a `joinByCode` callable is a feature of its own (F-113 candidate).
- The owner `maxMembers` raise on league UPDATE (F-105 step B) stays by the owner's decision until one real expansion purchase is proven.
- App Check is warn-only on every callable; enforcement is a config flip once the logs show no legitimate token-less traffic.
- Chat message / reply key and size constraints; a Firestore TTL policy on `moonshotQuotes.expiresAt`; per-user rate limits on `renameTeam` / `moonshotQuote`.
