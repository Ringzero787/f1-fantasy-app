# F-112 — UC: Security review 2026-10 hardening before the 2.5.0 build

Created: 2026-10-07 · Merged 2026-10-07 (PR #191) · Status: implemented · Design source: four security audits run on 2026-10-07 over the Moonshot server, the app code in the 2.5.0 build, the Pit Wall portal, and the rules / callables / ops surfaces

## Goal
Undercut (root app). Before the first store build that carries Moonshot, close what the review found. Nothing found was exploitable by a player with a modified client — ownership, pricing authority, idempotency and the rules deny-lists all held — but one failure mode was serious (settlement on an empty classification), several mediums were cheap to close, and a few hygiene items had been noted more than once.

## Acceptance criteria
- [x] **Settlement needs a classification.** `settleMoonshotsForRace` settles nothing unless the race is cancelled, or `completed` with a non-empty `results.raceResults`; an empty or half-ingested classification with DNS = LOSS would otherwise mark every open call MISSED permanently (test: empty results → no writes). Recovery: the scoring trigger fires on the transition to `completed`, so if that write carried no classification the calls stay LOCKED until `calculatePointsManually` or `repairTeamScoring` (whose head runs settlement) is run once the results are in — the same step scoring itself needs then.
- [x] **Confirm reads the token document.** `moonshotConfirm` reads `moonshotTokens/{team}_{season}` inside the transaction before writing it, so two confirms for one team contend on a document both have read (Firestore aborts on a changed read set), not only both write.
- [x] **Points balance is the ranked total.** Eligibility's POINTS balance is `memberSeasonTotal(team)` (active + banked + Moonshot), so a team in the red from earlier calls cannot keep risking its gross points.
- [x] **Full-mode repair cannot erase settled cash Moonshots.** Full mode is already refused outright (`Full rebuild is disabled`); the new guard is the belt for the day it is switched back on — the run aborts before any write when a team in scope has `moonshotStats.cashRisked > 0`, because rebuilding `budget` from `totalSpent` would refund misses and erase hits. Incremental repair never rebuilds `budget`. No test: the path is unreachable today.
- [x] **Bounded quotes.** A quote document is one per (team, race, driver, prediction, target, currency, stake, tokens-used) tuple — a re-quote overwrites — so a script cannot grow `moonshotQuotes` beyond tuples × tokens. The tokens-used count in the id means a confirmed quote is never overwritten (its `used` flag and `moonshotId` link survive); a re-quote while a confirm is in flight on the same tuple makes that confirm settle on the newer price, same stake. Confirm still checks `used` and `expiresAt`; the id is refused if it would exceed confirm's 128-char cap; `predictionTarget` is dropped for every type but `EXACT_FINISH` before it reaches the id (it was unvalidated for the others and could vary the id without bound).
- [x] **Input hygiene.** Ids capped at 128 chars; model driver lookups are own-property reads (no `constructor`/`__proto__` keys); the live sweep accepts only whole car numbers and positions 1–30 and an integer session key (test: fractional car, position 0/31/string); config clamps `vig` 0–0.5, `minMultiplier` 0.1–2, `maxMultiplier` 1–50, `tokensPerTeam` 1–20, `maxPerRace` 1–5, and a `NaN` pricing field (Firestore stores them) falls back to the default instead of pricing as NaN (test). The id cap and own-property reads sit inside the callables and have no unit test.
- [x] **Handoff rate limit on the client address.** `pw-redeemPortalHandoff` keys its limit on the **last** `x-forwarded-for` hop — the one Google's front end appends; the earlier hops are the caller's to type — not on Cloud Run's proxy address, so one key is no longer shared by every portal sign-in and a caller cannot mint a fresh key per request (`clientIpOf`, test).
- [x] **Rules: league content is for approved members.** `raceResults`, `activity`, `invites`, `announcements` (+ replies) and `messages` read with `isApprovedLeagueMember` (owner and, where it was, admin kept); a join awaiting approval reads the member list and — deliberately, because released clients enrich that list from `fantasyTeams` while a join is pending — the league's teams, nothing else (test). `fantasyTeams` and `notifications` lists are scoped: a team list must be the owner's own or one league's; a notifications list the owner's own. Every shipped client query carries those filters (rules tests replay them). The one that does not — the global team-name query of builds before 2.3.2 (F-059 step A moved it to `checkTeamNameAvailable` on 2026-09-19) — is refused, so `functions/scripts/setAppVersionGate.js` raises `config/app.minVersion` (op-script convention, `uc-script` kind) and is applied **before** the rules deploy: an old device sees the update screen, not a failed rename. The floor shipped as **2.3.2** — the minimum the scoped `fantasyTeams` list rule needs — on 2026-10-09. It was planned as 2.5.0 (the owner's decision after the build: every store onto the Moonshot build together), but that is a separate product decision with a stricter precondition, and bundling the two held this security fix undeployed; the 2.5.0 force-update is deferred to its own feature and op. **Precondition for the gate op, and so for the rules deploy:** the floor must be at or below what is live on the **oldest** store — not what has been built — because the floor blocks all three at once and the Amazon build's update button opens the Play URL (`AppUpdateGate.openStore` has no Amazon branch), so a blocked Fire OS user cannot reach their own store at all. Live at 2026-10-09: Play 2.5.1, App Store 2.5.0, Amazon 2.4.3 — the oldest is Amazon's 2.4.3, which clears 2.3.2 and would **not** have cleared 2.5.0. Amazon has no API, so that version is always a question for the owner, and `scripts/versionGate.test.js` now ties the floor to the live set declared in the script header so it cannot be raised silently.
- [x] **App.** The menu is coerced like the call (`toMenu`: arrays default empty, balances to 0, server band labels through the vocabulary check) so a partial answer cannot throw in a render; announcements load per league with a per-league catch, so a league whose join is still pending (now refused by the rules) does not hide the others'; the tutorial flag is an `updateDoc` (no ghost `users` document); one confirm in flight at a time; a persisted demo session is dropped on hydrate in a build that does not allow demo.
- [x] **Portal.** The Season tile's record lines never throw or print NaN on a partial `moonshotStats` (numbers through `n()`, `biggestHit` only when its driver and amount are well-formed).
- [x] **Repo.** The three unguarded root scratch scripts are removed; `.gitignore` covers `*.p8`, `*.p12`, `*.mobileprovision`, `.env.production`.

## Noted, not changed here (owner decisions or larger work)
- **A 2.4.3 floor is available and would retire the Amazon sign-in takeover primitive.** The
  security read of 2026-10-09 replayed every `fantasyTeams` and `notifications` query at
  `uc-v2.3.2`, `uc-v2.3.4`, `uc-v2.4.3` and `uc-v2.5.1` and confirmed **2.3.2 is sufficient for the
  rules this feature added**. But 2.4.3 is the first build with the legacy Amazon flow deleted
  (F-094) — the one that hands an authorization code to a claimable custom scheme — and 2.4.3 is
  exactly the oldest live store, so the same store precondition allows it. Not taken: on 2.4.3+ the
  replacement web flow is gated off until the Login with Amazon return URL is registered, so a Fire
  OS user signing out or installing fresh could have no Amazon sign-in. Signed-in users are
  unaffected. **Owner decision, once that URL is registered.**
- **Applying any floor is what makes the Fire OS dead end live**, since `minVersion` was absent
  before. `AppUpdateGate.openStore` has no Amazon branch, and no app-side fix can reach a build
  already installed below the floor — which is precisely who sees the screen. Mitigated in
  `updateMessage`, which is read from Firestore and so does reach them: it now tells Fire tablet
  users to open the Amazon Appstore themselves and says the button cannot. The app-side `amazonUrl`
  branch is still worth adding for future floors.
- **Builds at or below 2.4.3 with a pending join read no announcements at all.**
  `getActiveAnnouncementsForLeagues` awaits each league in a loop, so one unapproved membership
  rejects the whole call and the store catches it into an empty list. Availability only, bounded,
  and it clears on approval; the floor cannot fix it while Amazon is live at 2.4.3.
- **The 2.5.0 force-update is deferred to its own feature and op.** It is a product decision, not a
  rule requirement, and its precondition is 2.5.0 or newer live on Play, the App Store **and**
  Amazon. Keeping it as a footnote here is how it ended up bundled with the security floor and
  stalled it. **OP-156 must not be applied for either purpose:** it was planned while `DESIRED`
  said 2.5.0 and its title says so, but from the current tree it would write 2.3.2.
- `leagues` is readable by any signed-in user and stores `inviteCode`, so codes can be harvested and approval-free leagues joined uninvited. The join flow in released clients queries by `inviteCode`; moving codes to `leagueCodes/{CODE}` or a `joinByCode` callable is a feature of its own (F-113 candidate).
- The owner `maxMembers` raise on league UPDATE (F-105 step B) stays by the owner's decision until one real expansion purchase is proven.
- App Check is warn-only on every callable; enforcement is a config flip once the logs show no legitimate token-less traffic.
- Chat message / reply key and size constraints; a Firestore TTL policy on `moonshotQuotes.expiresAt`; per-user rate limits on `renameTeam` / `moonshotQuote`.
- An Amazon store URL in `config/app` for the update gate (it falls back to the Play URL); a `.gitattributes` to settle line endings (several files are CRLF).
- The PR workflow's root `npm ci` runs lifecycle scripts; the file is rendered by `aidlc sync` from the engine template, so `--ignore-scripts` there is an engine change, not a repo edit.

## Data
No new collections. `moonshotQuotes` ids become deterministic per tuple. `config/app.minVersion` = `2.3.2` (was unset) — the minimum the scoped list rule needs, applied 2026-10-09; `updateMessage` names the three stores (the force screen on an Amazon install opens the Play URL); `latestVersion` untouched, and deliberately so: moving it starts showing the dismissible banner, whose button has the same Amazon problem. The 2.5.0 force-update — every store onto the Moonshot build — is deferred to its own feature and op, and needs 2.5.0 live on all three.
