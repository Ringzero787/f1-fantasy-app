# F-054 — UC: Standings movement and best-race fields

Created: 2026-09-18 · Status: planned

## Goal

The Grid standings show `▲ 1 / ▼ 2 / —` per player and the Profile shows a BEST race score, but neither had a data source: nothing stored a member's rank before the last race, and per-race team totals only existed as `lastRacePoints`. This server-side feature writes `previousRank` on each league member (snapshotted once per race weekend, on the first ranking pass for that race id — qualifying, sprint or race) and `bestRacePoints` (+ `bestRaceId`) on each team when a race is scored. Nothing is backfilled: per-race team totals and ranks were never stored, so both fields populate from the next scored round onward and the app shows `—` until then.

## Acceptance criteria
- [ ] `rankLeagueMembers(leagueId, raceId)` (qualifying, sprint and race passes) writes `rank` for every member and, on the first pass for that `raceId`, `previousRank` = the member's rank before the weekend plus `previousRankRaceId`; later passes in the same weekend leave the snapshot alone; repairs (no race id) write `rank` only.
- [ ] Phase 1 of `onRaceCompleted` merges `bestRacePoints` / `bestRaceId` onto a `fantasyTeams` doc when the weekend's team total exceeds the stored best (the first scored round sets it).
- [ ] `repairTeamScoring` re-ranks without touching the snapshot (rank only).
- [ ] `firestore.rules` adds `bestRacePoints` / `bestRaceId` to the client deny-list on `fantasyTeams` updates (server-owned; a forged best would otherwise stick). Member `previousRank*` fields stay client-writable until F-056 tightens member self-updates.
- [ ] No backfill (nothing reliable to reconstruct); deploy goes through `aidlc op functions-deploy` and `aidlc op rules-deploy` before the next scored round.
- [ ] Standings movement cell renders from `previousRank − rank` (`src/simple/grid/standings.ts`, F-051); Profile BEST renders `bestRacePoints` (`src/simple/grid/raceHistory.ts`, F-052); both show `—` when absent.
- [ ] `node --test functions/test/standingsFields.test.js` covers ordering, the once-per-weekend snapshot, first-time members, repairs and best-race promotion; jest covers the client formatting (F-051 / F-052).

## Data
Four derived fields (`previousRank`, `previousRankRaceId` on league members; `bestRacePoints`, `bestRaceId` on the user's own team); no new categories.

## Performance budget
`rankLeagueMembers`: same single members read; each write carries at most two extra fields. `onRaceCompleted` Phase 1: two extra fields on writes it already performs; no extra reads.

## Out of scope
- Full per-race points history.
- Backfilling movement or best race for rounds already scored.
- Tightening client writes to league member docs (F-056).
