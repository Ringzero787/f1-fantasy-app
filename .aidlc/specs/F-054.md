# F-054 — UC: Standings movement and best-race fields

Created: 2026-09-18 · Status: planned

## Goal

The Grid standings show `▲ 1 / ▼ 2 / —` per player and the Profile shows a BEST race score, but neither has a data source: nothing stores a member's rank before the last race, and per-race team totals are only kept as `lastRacePoints`. This server-side feature writes `previousRank` on each league member and `bestRacePoints` (+ `bestRaceId`) on each team when a race completes, backfills what can be reconstructed from `raceScores`, and the app reads them.

## Acceptance criteria
- [ ] `onRaceCompleted` (Undercut functions) writes `previousRank` = the member's rank before this race's points were applied, alongside the existing `rank` / `lastRacePoints` update, for every member of every league.
- [ ] The same handler sets `bestRacePoints` / `bestRaceId` on a `fantasyTeams` doc when the race total exceeds the stored best.
- [ ] `repairTeamScoring` and the manual re-score path keep both fields consistent.
- [ ] A one-time backfill runs through `aidlc op` (kind `uc-script`), dry-run shows per-league/team diffs, apply writes them; backup lands on the SMB share.
- [ ] Standings movement cell renders from `previousRank − rank`; Profile BEST renders `bestRacePoints`; both show `—` when absent.
- [ ] `node --test functions/test/*.test.js` covers rank-before/after and best-race promotion; jest covers the client formatting.

## Targets
- functions
- android

## Data
Two derived fields on the user's own team and league-member documents; no new categories.

## Performance budget
`onRaceCompleted`: one extra field per member/team in writes it already performs; no extra reads.

## Out of scope
- Full per-race points history.
