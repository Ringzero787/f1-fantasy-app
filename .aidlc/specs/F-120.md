# F-120 — UC: League round report after each race

Created: 2026-10-11 · Status: building · Asked for by the owner, 2026-10-11, with a screenshot of
another fantasy game's end-of-race screen: "clean, easy and shows who made the most progress …
this summary is for folks in a league that want to see how they compare. This could be a button
next to season under league, but also … a 'next' when you get the conclusion of the race."

## Goal
Undercut (app only; no server, rules or portal change). After a race a manager already gets a
weekend recap of their own team (what each pick scored) and can look back at one race's league
table (F-062). What is missing is the short answer a league wants on Sunday night: who won the
round, who made the most progress, who had a bad one. The round report is that answer on one
screen, in the Grid's own type and cards: your place, the podium, then callouts in pairs. It opens
from the League tab beside the season selector, and as the next step after the weekend recap.

## Acceptance criteria
- [x] **One rule set, in one pure module** (`src/simple/grid/roundReport.ts`, unit-tested): the
      report is built from the league's leaderboard for the race and the one for the round before,
      both documents F-062 already writes. No new server data.
- [x] **Your round first**: place of how many, race points, and the change against your own
      previous round when there is one to compare (tests).
- [x] **Podium**: places one to three in rank order with points; a tie for a place stays on it,
      capped at five rows (tests).
- [x] **Biggest climb and biggest drop**: the largest gain and loss in race points against each
      manager's *own* previous round. Only managers scored in both rounds are compared; no climb
      is named when nobody gained and no drop when nobody lost; the first round on record has
      neither (tests).
- [x] **Top score and low score**: most and fewest race points. The low score is left out when
      everyone is level or the league has fewer than three managers scored (tests).
- [x] **Moonshot hit and miss**: the largest settled Moonshot gain and loss of the round, shown
      only when somebody called one (tests).
- [x] **Ties share a callout**, the viewer named first as YOU, three or more as "NAME & N OTHERS"
      (tests). A callout the viewer is in is outlined.
- [x] **Approximate data says so**: a leaderboard rebuilt from race-day points (F-062
      `estimated`) carries the same note the race table does (tests for the flag).
- [x] **From the League tab**: a REPORT link beside the selector, for the race on screen or the
      latest race while the season table is showing; absent until the league has a leaderboard
      (`F-120-ios-league-report-link.png`, `F-120-ios-report-sheet.png`).
- [x] **From the weekend recap**: when the league has a leaderboard for that race the recap's main
      button is NEXT · HOW THE LEAGUE DID, with GOT IT beneath it; the report is the same card's
      second step, ending in DONE. With no league or no leaderboard the recap ends in GOT IT as
      before (`F-120-ios-recap-next.png`, `F-120-ios-recap-report-step.png`).
- [x] **Two reads at most**, cached for the session and cleared by pull-to-refresh on the League
      tab.
- [x] **Large display sizes**: callouts stack one per row above size L.

## Targets
- android
- ios
- amazon

## Data
No new user data and nothing written. Reads `leagues/{id}/raceResults/{raceId}` for two races,
which league members can already read and the League tab already shows as a table: other members'
display names, team names and race points. Nothing leaves the device.

## Performance budget
Up to two document reads when a report is opened, none otherwise. No new dependency.

## Out of scope
- **Points per dollar of roster ("efficiency")**, which the reference screen has. The leaderboard
  documents do not record what each roster cost at lock, so it needs a server change (F-062's
  writer) and cannot be backfilled exactly for past rounds. Proposed as a follow-up.
- Movement in the season standings caused by the round (the season table already shows it).
- Sharing the report as text or an image.
- Avatars on the rows; the Grid league table does not use them either.

## Verification
iOS simulator (Release build, demo data): the REPORT link, the sheet and its scroll, and the
recap's second step. The recap does not appear in demo mode, so for the two recap screenshots the
verification copy (never committed) forced it to show; that proves the layout and the hand-over
between the two steps, not the condition that offers the button. Not checked: Android, a live
league, display size XXL, dark theme, a screen reader, and a league whose latest race has no
previous round.
