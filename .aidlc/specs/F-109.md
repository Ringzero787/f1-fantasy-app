# F-109 — UC: Moonshot in Pit Wall

Created: 2026-10-06 · Status: implemented · Design source: `docs/design/moonshot/SPEC.md` §16, §21, §28–§30

## Goal
Undercut (root app), Pit Wall portal. The portal is where a manager studies a call before making it and follows it afterwards: every driver's Moonshot predictions priced from the same snapshot the app uses, the team's open and settled Moonshots on the Briefing, the league's declared Moonshots, and — for pass holders — the model view behind a multiplier. Placing a call from the web uses the same callables as the app.

## Acceptance criteria
- [ ] **Pricing is free.** The driver slide-over gains a MOONSHOT tab showing the predictions with model chance, band and multiplier for every signed-in user, because the price has to be visible to everyone. The source is the same as the app's: the `moonshotMenu` callable (F-106/F-108) prices each enabled prediction from the published model — there is no `pw_moonshot_odds` document; the model lives in `moonshotModels/{raceId}`, which the rules open to any signed-in user. The pass adds the "why this multiplier" depth: the finishing-position distribution as a bar chart (the `.bars` primitive + its table), the predicted/expected finish and likely range. Circuit and form splits and the season calibration need data the Pit Wall worker does not publish yet — a follow-up once F-070's calibration gate produces it.
- [ ] **Call from the web**: the MOONSHOT tab runs the same currency → prediction → stake → confirm flow through `moonshotQuote` / `moonshotConfirm` / `moonshotCancel` (F-106), with the same two-tap minimum, the exact Hit/Miss numbers before confirm, a re-fetch of an expired quote that stays on the confirmation when the terms moved, Double Down framing and EXACT FINISH when enabled; the web never writes `moonshots`. The portal had no race id anywhere; `loadCurrentRace` reads it from the same `races` query the account header uses.
- [ ] **Lineup Lab** (owner's ask 2026-10-07: "moonshot is on the main home pages but not on lineup lab"): the Lab is where drivers are studied, so a call starts there too — a 🚀 on every driver row of the options table (opens the driver's MOONSHOT tab without swapping him in), a "🚀 Moonshot on {driver}" button under the selected driver's top-pick frame, the roster tile wearing the 🚀 like the Briefing's, and the "Your Moonshot" tile beside the roster. The Lab's entry points and the Briefing's tile share one `useMoonshotEntry` hook (a real team, a round to price, the calls loaded, not the example payload), so they agree on when a call can start and open the driver on the MOONSHOT tab the same way; keyboard activation of a row's 🚀 does not also trigger the row's swap.
- [ ] **Briefing**: a "Your Moonshot" tile under the lineup when one is called for the round (prediction, chance, stake, Hit/Miss, state; Cancel before lock from the driver's MOONSHOT tab — change = cancel and call again, one call per race), and tokens left when none is; after settlement the result line. The lineup tiles mark the Moonshot driver with a 🚀 pill.
- [ ] **League**: locked Moonshots of league-mates on the Briefing's rivals frame ("Turn One called Hadjar Podium · 200 pts · 5×"), private until lock — from the `moonshotLeagueBoard` callable, which decides "locked" on the server clock (both the call's stamped lock and the race's live lock passed), so the portal needs no list query on `moonshots`.
- [ ] **Standings and recap**: the Season page gains a "Moonshots · this season" tile with the team's record (used, hit/missed, hit rate, points and cash risked/won, biggest hit) and its Moonshot points, from the team document's F-107 columns. The portal has no league standings table today (its league view is the Briefing's rivals frame from the worker's `pw_leagues` document), so the `MOONSHOT` column and the league-wide award candidates of SPEC §30 wait for a standings frame — a follow-up that needs the worker to carry `moonshotPoints`/`moonshotStats` per team.
- [ ] Scroll budget and click-in rules of F-075 hold (2026-10-07: `scripts/ops/pitwall-pages-deploy.sh dryrun` — 326 states within 3.0 screens, first-load JS 150 KB gzip of the 250 KB budget); terminology rule as F-108 (the copy is tested against the forbidden list); locked (no-pass) treatment only on the depth view (`entity.moonshotModel`), never on the price (`entity.moonshot` is free). The Moonshot frames render only with a real team — the example payload and the preview build make no Moonshot request — so they are verified on `pitwall.humannpc.com` after the pages deploy with a signed-in account, not by example-mode screenshots.

## Targets
- web

## Data
Reads, all with the signed-in user and only once a real team is loaded: the current `races` document (the id the callables need), the team's own `moonshots` (owner list), `moonshotModels/{raceId}` (public pricing data, the depth view's chart), the team document's `moonshotPoints`/`moonshotStats`; callables `moonshotLeagueBoard` (the league's locked calls, decided on the server clock) and `moonshotMenu` per opened driver (cached per driver until a confirm or cancel). Writes only through `moonshotQuote` / `moonshotConfirm` / `moonshotCancel`. The example payload and the preview build make no Moonshot request.

## Performance budget
Per signed-in Briefing view: three reads (race, own calls, model) and one callable (board). Per driver opened on the MOONSHOT tab: one callable (menu), then one per quote.

## Out of scope
- Pricing, eligibility, settlement (F-106/F-107).
- The app experience (F-108).
