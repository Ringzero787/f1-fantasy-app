# F-163 — UC: admin stats aggregator

Created: 2026-11-19 · Status: planned

## Goal

The owner's admin site (admin.humannpc.com) has one App Stats page for every studio app. QuiltWall
already feeds it: a daily function writes a stats document and a dated history snapshot, and the
page's Refresh runs the same aggregation on demand. Undercut has nothing: the old admin tab counted
whole collections in the browser and had no active users, signups trend, pass counts or history.
This adds the same aggregator to Undercut, writing the shared contract to `admin/projects/undercut/`,
plus the admin-only read rule the page needs.

## Acceptance criteria
- [ ] `functions/src/admin/statsCore.ts` (pure): `buildUndercutStats` returns `schema: 1`, `app: 'undercut'`, `updatedAt`, `totalUsers` (docs in `users`), `newUsersToday` / `newUsersWeek` (rolling 24 h / 7 d by `createdAt`), `activeUsersDay/Week/Month` (rolling 1/7/30 d), `activeSource: 'auth-refresh'`, `paidSubscribers` (live pass via `pitwall/pass.ts passActive`, not a league trial), `trialUsers` (live pass with `ref: 'league_trial'`), `freeUsers` (the rest), `estimatedMRR: null` (the pass is per season, not monthly), `signupsByDay` (30 zero-filled UTC days), `content`, `usage` (`{today, all}` per feature) and `health.errors24h`.
- [ ] Active users come from Firebase Auth: the later of `lastSignInTime` and `lastRefreshTime` (an open app refreshes its ID token hourly), counted only over uids that have an Undercut `users` doc, so a Track Limits-only account in the shared Auth pool is not counted.
- [ ] `functions/src/admin/adminStats.ts`: `aggregateAdminStats` runs daily at 06:00 America/Chicago; `getAdminStats` (callable) runs it on demand and refuses a caller without the `admin` claim. Both write `admin/projects/undercut/stats` and `admin/projects/undercut/history_<UTC date>`.
- [ ] The aggregator only reads player data (counts, `createdAt`, `pass`, Auth metadata) and writes nothing outside `admin/projects/undercut/`. `errors24h` counts `errorLogs` from the last 24 h whose `app` is not `tracklimits`.
- [ ] `firestore.rules`: `admin/projects/{app}/{docId}` is readable with the admin claim and not writable from any client (rules test).
- [ ] Tests: `functions/test/adminStats.test.js` (toMillis, signups by day, active windows, pass split, new-user windows, contract fields); rules suite passes.

## Targets
- Cloud Functions (default codebase), Firestore rules. No app build.

## Data
No new user data is collected. The aggregator reads existing data server-side (user `createdAt`,
`pass`, Firebase Auth sign-in/refresh times) and stores only totals and per-day counts under
`admin/projects/undercut/`, readable only with the admin claim. No per-user rows, emails or uids
are written.

## Performance budget
One daily run plus manual refreshes: one `users` read (two fields), one Auth `listUsers` page per
1000 accounts, and count aggregations. No change to the app.

## Out of scope
- In-app activity telemetry (a heartbeat on app open). Auth refresh time is the proxy until an app release adds one.
- Track Limits stats: Track Limits owns its own aggregator in Ringzero787/tracklimits, writing `admin/projects/tracklimits/`. The read rule here covers it, since the ruleset lives in this repo.
