# F-163 — UC: test account flag

Created: 2026-11-19 · Status: planned

## Goal

The owner quotes player numbers from the admin page (admin.humannpc.com/#undercut), and they overstate the real player base by about half. A read-only survey of production on 2026-11-19 found:
- 124 user documents;
- 55 store tester devices (a gmail address that is the display name run together plus `.NNNNN`, never active after day one, arriving in bursts around store builds);
- 1 Google test-lab account;
- 3 Amazon reviewers.

This feature marks those accounts `testAccount` on their user document, makes the mark server-owned, and has the admin page count players without them.

## Acceptance criteria
- [x] `functions/src/users/testAccounts.ts` classifies an account as `tester-farm`, `test-lab` or `store-reviewer`, and anyone active 24 h or more after signing up as a player whatever their address. `functions/test/testAccounts.test.js` covers each rule from both sides.
- [x] `firestore.rules`: a user can neither create their document with `testAccount` nor add, change or remove it later. A marked user can still save their own fields. Tested in `rules-tests/firestore.rules.test.js`.
- [x] `functions/scripts/markTestAccounts.js` runs as a dry run by default and prints counts and uid prefixes only, never names or addresses. With `--apply` it writes `testAccount: { reason, markedAt, by: 'F-163' }`. It only adds marks and skips admins, already-marked users and uids in `KEEP`.
- [x] The 2026-11-19 dry run against production marks 59 (55 tester-farm, 1 test-lab, 3 store-reviewer) and leaves 65 players.
- [ ] The rules are deployed with a `rules-deploy` op before the mark is written, so no client can remove it.
- [ ] The marks are written with a `uc-script` op (`script=markTestAccounts.js`, `backup=users`).
- [ ] The admin page (humannpc-website `admin/undercut-admin.js`):
  - shows players and test accounts separately in the user and team counts;
  - tags marked users in the user list.

## Targets
- backend (Firestore rules, an ops script)
- web (the admin page, in the humannpc-website repo)

## Data
- Stored: the new field `users/{uid}.testAccount`, holding a reason code, a timestamp and the feature id. It holds no new personal data.
- Read: the classifier reads each account's email address, display name and Auth sign-up and last-active times. It runs on the build box only.
- Output: names and addresses are never logged or written anywhere. The op log holds counts and 8-character uid prefixes.
- Who can read the mark: the user themselves and the admin account. Both can already read the whole document.

## Performance budget
n/a: one script run, and the admin page filters in memory.

## Out of scope
- Deleting test accounts or their teams. They stay playable, and a tester who later plays keeps playing.
- Unmarking automatically. A mistaken mark is removed by hand through an op, and the uid goes into `KEEP`.
- Filtering test accounts out of push broadcasts, league standings or the season rollover.
- The 191 Auth accounts with no user document (mostly May 2026 pre-launch testing).
