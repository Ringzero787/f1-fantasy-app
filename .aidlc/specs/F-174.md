# F-174 — UC: server-driven notice banner on the Team panel

Created: 2026-11-24 · Status: building

## Goal
After the 2026→2027 season rollover (mid-December), every Undercut team resets to an empty lineup with $1,000. Today the app shows that with no explanation, while the owner is ramping up advertising. Owner decision, 2026-11-24: the 2.9.0 store build gets a **server-driven notice banner** at the top of the Grid Team panel. Its text lives in `config/app.notice`, so it can be set, changed or withdrawn at any time without a build ("Your team has been reset for 2027…", "Round 1 is close", …).

This is the only player-facing change added to 2.9.0, so it is deliberately small: one optional config field, a fail-closed parser, one card, a local dismissal list.

## Acceptance criteria
- [x] `config/app.notice` is parsed by `parseNotice` (`src/simple/grid/notice.ts`). Anything malformed means **no banner** (fail closed), never a partial one. Rules below.
- [x] The banner renders at the top of the Team panel (`src/simple/grid/GridTeamPanel.tsx`), directly under the header, only when the notice is valid, inside its time window, inside its version bounds and not dismissed on this device (`noticeToShow`). The window is re-checked as the panel's one-minute clock ticks.
- [x] With no notice (absent, malformed, out of window, other version, dismissed) nothing renders and the layout is unchanged.
- [x] The player can dismiss it (✕). The dismissal is stored per notice `id` in AsyncStorage (`src/store/notice.store.ts`, key `notice-dismissals`, newest 20 ids kept), so a notice with a new `id` shows again. It is per device and is never sent anywhere.
- [x] Text is rendered as plain React Native `<Text>`: no HTML, no markdown, no WebView. Line breaks in the body are kept.
- [x] A link is shown ("MORE →") only for an allowed URL, checked at parse time and again when pressed; any other URL drops the link and keeps the notice.
- [x] Grid design: `colors.card` fill, 14 px radius, `borderStrong` border (`warning` for `tone: 'warn'`), mono kicker (NOTICE / HEADS UP), Archivo title and body, theme tokens only. No line limits, so it wraps at display size XXL and at any OS font scale; the dismiss control keeps its own 44 × 44 column.
- [x] Accessible: the text block is one element read as "Notice: <title>. <body>"; the dismiss control is a button labelled "Dismiss notice"; the link is a `link` labelled "More about <title>".
- [x] Tests: `__tests__/simple/notice.test.ts` (parser valid / missing fields / over-long text / bad URLs / time window / version bounds / dismissal list) and `__tests__/simple/noticeWiring.test.ts` (the persisted dismissal store, and the panel wiring read off the source: this jest setup cannot render React Native components).

## Config shape
`config/app.notice`, optional:

```
notice: {
  id: string,            // required. 1–64 of [A-Za-z0-9._-]. The dismissal key: change it to show a notice again.
  title: string,         // required. 1–80 characters after trimming, one line.
  body: string,          // required. 1–500 characters after trimming; line breaks allowed.
  tone?: 'info' | 'warn',// default 'info'. 'warn' gives an orange border and the HEADS UP kicker.
  from?: string,         // ISO 8601 with a zone (Z or ±hh:mm). Shown from this instant (inclusive).
  until?: string,        // ISO 8601 with a zone. Hidden from this instant on (exclusive). Must be after `from`.
  minVersion?: string,   // dotted numbers ("2.9.0"). Shown only on app versions >= this.
  maxVersion?: string,   // dotted numbers. Shown only on app versions <= this. Must not be below minVersion.
  url?: string,          // optional "MORE →" link; see below.
}
```

Validation (`parseNotice`, `noticeToShow`):
- `notice` must be a plain object. A missing or wrong-typed `id`, `title` or `body` → no banner.
- `title` over 80 or `body` over 500 characters (after trimming) → no banner. A line break in `title` → no banner.
- Control characters (other than a line break in `body`), zero-width characters and bidi overrides anywhere in `title` or `body` → no banner.
- `tone` other than `info` / `warn` → no banner.
- `from` / `until`: an ISO string without a zone, any other string or a number → no banner. A Firestore Timestamp is also accepted (an op that writes a JS `Date` stores one). `until <= from` → no banner.
- `minVersion` / `maxVersion` not dotted numbers (e.g. `2.9.0-beta`) → no banner; `minVersion > maxVersion` → no banner. When either bound is set and the app's own version is unknown or not dotted numbers, the notice is hidden.
- `url`: allowed only if it is `https://` on `humannpc.com` or a subdomain of it (`undercut.humannpc.com`, `pitwall.humannpc.com`), with no userinfo, port, whitespace or backslash, at most 300 characters; or a store link accepted by `isStoreUrl` (`src/config/storeLinks.ts`: https on play.google.com, apps.apple.com, amazon.com, or the Amazon Appstore deep link). Anything else (http, another host, `javascript:`, `intent:` …) drops the link only.
- Unknown keys are **ignored**, not refused, so a later build can add a field without blanking the notice on 2.9.0. A misspelt key (`untill`) is therefore silent: write the keys exactly as above.

### Example: the season reset (from the F-155 notice text)

```json
{
  "notice": {
    "id": "season-reset-2027",
    "title": "Undercut 2027: every team starts fresh",
    "body": "The 2026 season is over. Every Undercut team starts again for 2027: an empty lineup, a $1,000 budget and zero points. Your team keeps its name and stays in its leagues, and your 2026 results are saved. The market is open all winter. Round 1 is Australia on 14 March 2027.",
    "tone": "info",
    "from": "2026-12-10T00:00:00Z",
    "until": "2027-03-16T00:00:00Z",
    "minVersion": "2.9.0"
  }
}
```

`from` should be set to the actual rollover time once it is scheduled (the notice should not appear before the teams are reset); `until` here is two days after the Australia race.

## Targets
- Undercut app (repo root): android, ios. Ships in **2.9.0**. Builds before 2.9.0 ignore the field.
- Files: `src/simple/grid/notice.ts`, `src/simple/grid/GridNoticeBanner.tsx`, `src/simple/hooks/useNotice.ts`, `src/store/notice.store.ts`, `src/simple/grid/GridTeamPanel.tsx`, `src/services/remoteConfig.service.ts` (type only).
- No functions, rules or index change. `config/{docId}` writes are already admin-claim only (`firestore.rules`); reads need a signed-in user, which the Team panel always has.

## Data
- Read: `config/app.notice`, through the config fetch the app already makes (`remoteConfigService.fetchAppConfig`). No new request, listener or collection.
- Stored on the device only: the list of dismissed notice ids (AsyncStorage `notice-dismissals`). Nothing is sent to the server or to analytics. No personal data.
- Setting, changing or removing the notice is an admin write to `config/app`, done as a uc-script op (not part of this feature).

## Performance budget
One `useMemo` over a small object, recomputed when the config, the dismissal list or the panel's one-minute clock changes. No network, no timers of its own.

## Known limits
- The app reads `config/app` once per launch, so a notice that is edited or withdrawn takes effect at the player's next app start. Inside a session only `until` ends it. Set `until` rather than relying on withdrawal.
- The notice text is English only, like the rest of the Grid panel's labels ("NOTICE", "HEADS UP", "MORE →"). The app ships 10 locales; per-locale notice text is a later change.
- The banner waits until this device's dismissals are loaded from storage, so a dismissed notice never flashes at start-up. A corrupted stored value is read as "nothing dismissed".

## Out of scope
- Sending the notice itself (writing `config/app.notice` in production): an op, run when the rollover is scheduled.
- The F-155 reset wording (the copy above is the F-155 text as given on 2026-11-24; F-155 owns it).
- A notice on any screen other than the Team panel, per-user or per-league targeting, analytics on views or dismissals, and the signed-out / no-team (create team) screens.
