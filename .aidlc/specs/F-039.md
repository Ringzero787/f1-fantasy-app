# F-039 — TL: Ben lines invariant checker gate

Created: 2026-09-11 · Status: building

## Goal
Ben's odds (`ben_lines`) are production data that settlement pays out on, and nothing validated them: odds at or below 1.00, inverted or unreachable ranges, best bets outside the race doc, stale lines the app hides, and edits after lock all pass silently today. `newgame/functions/scripts/checkBenLines.js` checks every lines doc for a race and prints findings in the AIDLC G15 protocol. It runs before and after each operation that writes lines (F-038), and on demand for a season sweep, so a bad line is caught before players can stake on it.

## Acceptance criteria
- [ ] Unit tests on synthetic docs cover each rule: inverted range and unreachable range (critical), a range covering every result (high), odds non-numeric or not above 1.00 (critical), a book under 100% (medium; high under 97%), a best bet outside the race session (high), a best-bet count other than 3 (medium), a missing active driver or constructor (high), an unknown entity (medium), a legacy entity without predictedLo/predictedHi (high), lines older than the last completed race (high), lines changed after their session locked (high).
- [ ] Valid one-sided best-bet ranges (driver 5–22, constructor 3–34) produce no findings.
- [ ] The live Madrid, Italy, Hungary and Netherlands docs produce no findings; future races beyond the next one with empty placeholder docs produce none either.
- [ ] `--fail-on=high` exits 2 when a high or critical finding exists and 0 otherwise (Madrid 0, Miami 2).
- [ ] G15 runs it as `ben-lines-before` (pre-apply, tl-best-bets) and `ben-lines-after` (post-apply, every lines kind); a high finding fails the gate.
- [ ] The checker never writes to Firestore.

## Targets
- backend: Firestore `ben_lines` (read-only) and the AIDLC ops tier.

## Data
No user data. Reads `ben_lines`, `races`, `drivers` and `constructors`.

## Performance budget
n/a — one run reads the race's 2–3 lines docs, the races list and the roster (a few seconds).

## Out of scope
- A calibration backtest of the model against results (advisory lookback report) — follow-up.
- Clamping odds in the writers so they cannot go below 1.00 — F-041.
- Moving these tests into the Track Limits test harness — F-040.
