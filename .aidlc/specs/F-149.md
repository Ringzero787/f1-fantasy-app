# F-149 — UC: season-aware results ingestion

Created: 2026-11-15 · Status: implemented

## Goal

Every OpenF1 job read one global year (`SEASON_YEAR = 2026`) and a hand-kept round → race id
table (`ROUND_TO_RACE_ID`, plus `SPRINT_ROUNDS`). A 2027 race document would be matched to the
2026 calendar by round number, so the first 2027 race would have been auto-approved with the 2026
Australian results, and the schedule monitor would have auto-cancelled a 2027 race the day it ran
because no 2026 session sat near it. The round table had already failed once: on 2026-10-01 the
sync wrote Bahrain's session times onto singapore_2026. The FY27 audit (2026-11-13) found it.

Now every job starts from the race document. Its `seasonId` (which must agree with the id's
`_YYYY` and the race time's year) picks the OpenF1 calendar, and the meeting is the one whose
not-cancelled Race session starts within three days of the document's race time. The car-number
table is one season's, so a race from any other season is held, with a log line that says what to
change, until `DRIVER_NUMBER_TO_ID` is updated and `DRIVER_TABLE_SEASON` bumped. Players see no
change in 2026; in 2027 results can never be scored from the wrong year.

## Acceptance criteria
- [x] `functions/src/ingestion/season.ts`: `seasonOfRace` returns the season only when `seasonId`, the race id year and the race time year agree, else null; `meetingForRace` returns the season's one meeting with a not-cancelled Race within ±3 days of the race time, else null (none, two, other season, cancelled).
- [x] The results check (main and correction pass), qualifying check, sprint check, schedule sync, schedule monitor and live sweep read no fixed year or round table; `SEASON_YEAR`, `ROUND_TO_RACE_ID`, `SPRINT_ROUNDS` and `deriveRoundNumbers` are gone (a test fails if an ingestion source names them).
- [x] A sprint weekend is one the document flags or one OpenF1 lists a Sprint for.
- [x] A race whose season is not `DRIVER_TABLE_SEASON` (2026) is never fetched, scored or swept; each job logs `NOT INGESTING <race>: car numbers are only known for 2026 — update DRIVER_NUMBER_TO_ID for <year> and set DRIVER_TABLE_SEASON = <year>`. Only races that are due (race time passed, or within three days for qualifying and sprint) are judged, so an early 2027 seed causes no noise.
- [x] The schedule monitor checks each race against its own season's sessions and never cancels a race whose season cannot be read.
- [x] Replay: the seeder's 23 live 2026 races each match their own meeting by circuit (Bahrain → Kuala Lumpur, Singapore → Singapore), sprint flags equal the meetings with a Sprint, and saudi_2026 matches nothing (`functions/test/season.test.js`, fixture `openf1Sessions2026.json` from `GET /v1/sessions?year=2026`). The same replay over the 24 production race documents: 24/24, none held.
- [x] The project test command passes: functions 261/261 (roundMapping.test.js retired, season.test.js +10), `__tests__/data/demoCalendar.test.ts` 4/4.

open races (3 today) in one query instead of up to 25 race documents one by one.
