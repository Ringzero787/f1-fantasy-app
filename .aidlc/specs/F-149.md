# F-149 — UC: season-aware results ingestion

Created: 2026-11-15 · Status: implemented

## Goal

Every OpenF1 job read one global year (`SEASON_YEAR = 2026`) and a hand-kept round → race id
table (`ROUND_TO_RACE_ID`, plus `SPRINT_ROUNDS`). A 2027 race document would be matched to the
2026 calendar by round number, so the first 2027 race would have been auto-approved with the 2026
Australian results, and the schedule monitor would have auto-cancelled a 2027 race the day it ran
because no 2026 session sat near it. The round table had already failed once: on 2026-10-01 the
sync wrote Bahrain's session times onto singapore_2026. The FY27 audit (2026-11-13) found it.

Now every job starts from the race document. Its `seasonId` (which must agree with the id's
`_YYYY` and the race time's year) picks the OpenF1 calendar, and the meeting is the one whose
not-cancelled Race session starts within three days of the document's race time. The car-number
table is one season's, so a race from any other season is held, with a log line that says what to
change, until `DRIVER_NUMBER_TO_ID` is updated and `DRIVER_TABLE_SEASON` bumped. Players see no
change in 2026; in 2027 results can never be scored from the wrong year.

## Acceptance criteria
- [x] `functions/src/ingestion/season.ts`: `seasonOfRace` returns the season only when `seasonId`, the race id year and the race time year agree, else null; `meetingForRace` returns the season's one meeting with exactly one not-cancelled Race within ±3 days of the race time, else null (none, two meetings, two Races, other season, cancelled).
- [x] The results check (main and correction pass), qualifying check, sprint check, schedule sync, schedule monitor, live sweep and the `checkRaceCalendar.js` ops check read no fixed year or round table; `SEASON_YEAR`, `ROUND_TO_RACE_ID`, `SPRINT_ROUNDS` and `deriveRoundNumbers` are gone (season.test.js fails if any of those sources names them).
- [x] A sprint weekend is one the document flags or one OpenF1 lists a Sprint for.
- [x] A race whose season is not `DRIVER_TABLE_SEASON` (2026) is never fetched, scored or swept. The results, qualifying and sprint checks log `NOT INGESTING <race>: car numbers are only known for 2026 — update DRIVER_NUMBER_TO_ID for <year> and set DRIVER_TABLE_SEASON = <year>`; the live sweep logs the same reason as `NOT SWEEPING`. Only races that are due (race time passed, or within three days for qualifying and sprint) are judged, so an early 2027 seed causes no noise.
- [x] The schedule sync follows a race-time change of up to 24 h and refuses a larger one (the window is centred on the stored time, so following every move would let the feed walk a race and its lock times); completed and cancelled races are not touched.
- [x] The schedule monitor checks each race against its own season's sessions. It never cancels a race whose season cannot be read or whose season OpenF1 lists no sessions for (both flagged `CHECK:`), flags a race with no strict match or a matched Race more than 24 h from its race time, and still auto-cancels, as before, a race with no OpenF1 session within 3 days on the day after it. The old branch that cancelled any past `upcoming` race whose round was missing from the round table is gone with the table; such a race stays open for the results check and the ops check.
- [x] Replay: the seeder's 23 live 2026 races each match their own meeting by circuit (Bahrain → Kuala Lumpur, Singapore → Singapore), sprint flags equal the meetings with a Sprint, and saudi_2026 matches nothing (`functions/test/season.test.js`, fixture `openf1Sessions2026.json`: the Race/Sprint/Qualifying calendar from `GET /v1/sessions?year=2026`). The same replay over the 24 production race documents gave 24/24, none held (one-off, recorded in the PR); `checkRaceCalendar.js` run read-only against production reports OK with the season check.
- [x] The jobs apply it (`functions/test/seasonJobs.test.js`, stubbed Firestore + the 2026 fixture): due-race selection, qualifying/sprint selection (no fetch for a held season), sync (2 h followed, 40 h refused, idempotent), monitor (flags, no cancel on an empty calendar, cancel of a dropped race), live sweep hold. Loosening the 24 h cap or the season gate in the build fails these tests.
- [x] The project test command passes: functions 267/267 (roundMapping.test.js retired; season.test.js +10, seasonJobs.test.js +6, with the monitor's 15-day / +25 h window edges), `__tests__/data/demoCalendar.test.ts` 4/4.

## Data

## Performance budget
One OpenF1 sessions call per season per run, as before. The qualifying and sprint checks read the
open races (3 today) in one query instead of up to 25 race documents one by one.
