# F-116 — UC: raise the update floor to 2.5.0 once every store has it

Created: 2026-10-09 · Status: planned · Design source: split out of F-112 on 2026-10-09, because
bundling it with that feature's security floor held the F-112 rules undeployed for two days

## Goal
Undercut (root app). Move every installed build onto 2.5.0 or newer — the Moonshot build, with the
F-099/F-101/F-103 fixes and the F-112 hardening — by raising `config/app.minVersion`. This is a
**product decision, not a rule requirement**: F-112's scoped list rules need only 2.3.2, which
shipped on 2026-10-09. Keeping the two in one constant meant the stricter precondition of this one
(2.5.0 live in all three stores) blocked the other, so it now stands alone with its own op.

## Acceptance criteria
- [ ] **`config/app.minVersion` is 2.5.0**, written by `functions/scripts/setAppVersionGate.js`
      through a fresh `uc-script` op — not OP-156, which was planned when `DESIRED` said 2.5.0 and
      from the current tree would write 2.3.2.
- [ ] **2.5.0 or newer is live in all three stores first**, and `KNOWN_LIVE` in that script says so
      with a current `asOf`. The script refuses otherwise: `refuseIfItWouldLockAnyoneOut` rejects a
      floor above the oldest live store before it connects, and at `--apply` a declaration older
      than 45 days is refused as stale. `scripts/versionGate.test.js` holds the same invariant.
      Amazon has no API, so its version is always an owner answer. At 2026-10-09: Play 2.5.1,
      App Store 2.5.0, **Amazon 2.4.3 — this is the blocker.**
- [ ] **The Fire OS dead end is fixed first, or accepted in writing.** `AppUpdateGate.openStore`
      picks `iosUrl`/`androidUrl` with no Amazon branch, so the forced screen's only button opens
      Google Play, which a Fire tablet cannot use. `src/utils/storeDetection.ts` already exports
      `isAmazonBuild`; the fix is an `amazonUrl` key in `config/app` plus that branch. It cannot
      help a build already installed below the floor, so `updateMessage` keeps naming the manual
      path as well.
- [ ] **`latestVersion` is moved in the same op**, so the dismissible "new version" banner starts
      working — it has sat at 2.1.7, below every shipping build, so it has never once appeared.
      Only once the `amazonUrl` branch is in, since that banner's button has the same problem.
- [ ] **The rules deploy is not waiting on this.** OP-154 goes behind the 2.3.2 floor; nothing in
      F-112 needs 2.5.0.

## Targets
- firebase (one Firestore document, `config/app`, via a `uc-script` op)
- android, ios, amazon — nothing is built for this; it changes what installed builds do

## Data
No new collections and no personal data. Writes `config/app.minVersion`, `latestVersion` and
`updateMessage`, which every client reads unauthenticated. The risk is availability, not privacy: a
floor above what a store serves is a hard block with no dismiss, and the device cannot undo it —
recovery is a rollback op.

## Out of scope
- **A 2.4.3 floor.** Separately worth doing: 2.4.3 is the first build with the legacy Amazon
  sign-in flow deleted (F-094), so that floor would retire the takeover primitive and unblock
  deleting the `signInWithAmazon` callable — and the oldest live store already allows it. It waits
  on the Login with Amazon return URL being registered, or a Fire OS user who signs out has no
  Amazon sign-in. Recorded under F-112's "Noted, not changed here".
