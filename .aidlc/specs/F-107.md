# F-107 — UC: Moonshot settlement and standings

Created: 2026-10-06 · Status: planned · Design source: `docs/design/moonshot/SPEC.md` §9, §10, §18, §19, §26–§30

## Goal
Undercut (root app). When a race is finalised, every locked Moonshot on it is settled by the same scoring run that writes `raceResults`: a hit adds the reward, a miss removes the stake, a void returns the token, and none of it can happen twice. Moonshot points stay a separate, visible column so the table shows what was earned by scoring and what was earned by nerve.

## Acceptance criteria
- [ ] Settlement runs inside the existing race scoring (`onRaceCompleted` / `calculatePointsManually` / `repairTeamScoring`) after classification is final, for every `moonshots` document with `status: LOCKED` on that race. Result from the official finishing position: `WIN` P1, `PODIUM` P1–3, `TOP_5` P1–5, `EXACT_FINISH` equals target. Classification by status: finished → compare; DNF → `dnfRule`; DNS → `dnsRule`; DSQ → `dsqRule`; race cancelled → `cancelledRule`. Pure decision function with tests for every rule and type.
- [ ] **Idempotent and auditable.** `settlementId = seasonId + raceId + moonshotId + settlementVersion`; the adjustment is applied in a transaction that writes `settlementId`, `officialDriverFinish`, `result`, `adjustmentAmount`, `settledAt` on the Moonshot and refuses if `settledAt` is already set. A repeated run changes nothing (test). Original probability, multiplier, stake, prediction, model version and lock time are never overwritten (SPEC §27).
- [ ] **Points.** The adjustment goes to `fantasyTeams.moonshotPoints` (new, server-owned, rules deny client writes), not to `totalPoints`/`lockedPoints`; the per-race record in `raceSnapshots/{raceId}.moonshot` and `leagues/{id}/raceResults/{raceId}` carries `racePoints`, `moonshotPoints`, `raceTotal` per member. Season standings order by `totalPoints + lockedPoints + moonshotPoints`; `maxSeasonMoonshotPointGain` caps the running positive total (a hit beyond the cap is paid up to the cap and marked `capped`).
- [ ] **Cash.** The adjustment is applied to `fantasyTeams.budget` through the same server path the roster callables use, never below zero (a miss larger than the bank takes the bank to zero and marks `shortfall`). A void creates no adjustment and returns the token.
- [ ] **Backfill-safe.** A race already scored before this ships has no Moonshots; the run is a no-op there. A repair replay of a race with settled Moonshots re-derives the same results and leaves the adjustments untouched.
- [ ] **League feed and history.** Settlement writes a feed entry per Moonshot (`HIT` / `MISSED` / `VOID`, SPEC §29) to the league's activity collection, and increments season stats on the team: used, hit, missed, points risked/won, cash risked/won, biggest hit. Recap awards (SPEC §30) read these; the awards page itself is F-065.
- [ ] Standings in the app and portal show a `MOONSHOT` column when any member has one; a team's row expands to `Race Points · Moonshot · Race Total · Season Total` (SPEC §28). Tests on the standings ordering with and without Moonshot points.

## Targets
- firebase (functions, rules)
- android, ios, amazon (standings column)
- web (standings column)

## Data
Adds server-owned `moonshotPoints` and `moonshotStats` to the team, settlement fields to the Moonshot, feed entries visible to league members. No new personal data.

## Performance budget
One transaction per locked Moonshot per race (≤ one per team), inside the existing scoring run.

## Out of scope
- Live race-day status (F-108 reads positions; settlement reads only the final classification).
- Season recap awards page (F-065 consumes the stats).
