# F-079 — UC: UI string extraction and localization

Created: 2026-09-24 · Status: building (scaffolding landed; screen conversion ongoing)

## Goal
Undercut ships worldwide in nine languages beyond English, chosen for F1's real markets: Spanish, Portuguese (Brazil), French, German, Italian, Dutch, Polish, Japanese and Chinese (Simplified). One build carries every locale; there are no per-language app versions. A player gets their device language automatically and can override it in Profile.

This spec covers the app chrome. Release notes and the store blurb already translate at release time.

## Acceptance criteria

**Infrastructure — done in this change**
- [x] `i18next` + `react-i18next` + `expo-localization` installed. `src/i18n/resolve.ts` holds the pure resolution logic (saved preference, then device locale, then English; regional tags `pt-PT`, `es-419`, `zh-Hant` match onto a shipped bundle). `src/i18n/index.ts` wires it to i18next and the device; `src/i18n/bootstrap.ts` wires it to stored prefs and is the single import at startup.
- [x] No flash of the wrong language on start: persisted prefs hydrate asynchronously, so bootstrap applies the saved choice on `onFinishHydration` rather than in a render effect, and subscribes to the store for later changes. This is sufficient because `LaunchReveal` holds the native splash via `preventAutoHideAsync()` until its own full-screen overlay has painted and then animates over the app, covering content for far longer than an AsyncStorage read, on warm starts and OTA reloads as well as cold. If that launch choreography is ever removed, gate the first render on `usePrefsStore.persist.hasHydrated()` instead — noted in `bootstrap.ts`.
- [x] Language choice persists in `prefs.store` and survives a restart; `LanguagePicker` sits in Profile under Display, beside the theme picker.
- [x] Source catalog at `src/i18n/locales/en.json`; the nine target catalogs are generated, never hand-edited.
- [x] Plural groups carry the categories each language actually needs: Polish one/few/many/other, Japanese and Chinese `other` only, the Romance languages one/many/other.
- [x] `.aidlc/aidlc.yaml` declares the catalogs, so G16 enforces key parity, placeholder parity and a coverage floor on every PR.
- [x] Auth screens (sign in, register, forgot password) converted as the reference pattern.
- [x] Tests in `__tests__/i18n/language.test.ts`: regional tag matching, saved-beats-device, a catalog exists per shipped language, every non-plural English key is covered, every language has at least the `other` plural form, and placeholders match English exactly.

**Conversion — the remaining work**
- [ ] Convert the rest of the app, area by area, adding each converted path to `localization.scan` in `.aidlc/aidlc.yaml` as it lands so the gate starts guarding it. Roughly 400 user-facing strings across 99 files. Suggested order, highest traffic first:
  1. `app/(tabs)/index.tsx` and the tab bar labels in `app/(tabs)/_layout.tsx`
  2. My Team: `app/(tabs)/my-team/**`
  3. Market: `app/(tabs)/market/**`
  4. Leagues and chat: `app/(tabs)/leagues/**`, `app/(tabs)/chat/**`
  5. Calendar: `app/(tabs)/calendar/**`
  6. Profile: `app/(tabs)/profile.tsx`
  7. Shared components: `src/components/**`, `src/simple/**`
  8. Admin screens last, or leave them English — they are staff-only (decide explicitly and record it here)
- [ ] After each area: `aidlc i18n sync` to fill the nine catalogs, then commit the catalogs with the screen change so the feature lands translated rather than leaving a gap.
- [ ] Numbers, dates and currency go through a locale-aware formatter, not string concatenation. Audit `toLocaleDateString`, `toFixed` and any hand-built "$" strings while converting.
- [ ] Give short or ambiguous keys a description so the translator has context; "Open", "Free", "Right" and "Ace" each translate several ways.
- [ ] Once the whole app is converted, set `gates.G16.blocking: block` so a missing translation stops a release.

**Store listings**
- [ ] Localized Play and App Store listings for the nine languages. Release notes and the blurb translate automatically; the long description, screenshots and keywords are a separate manual pass in each console.

## Targets
undercut (root app: `app/`, `src/`)

## Data
No user data. Language preference is stored on-device only.

## Performance budget
Bundle grows by the i18n runtime plus nine catalogs. At the current 43 keys that is a few KB; at the full ~400 strings expect roughly 150-250 KB of JSON across nine languages. Watch `bundle_bytes` in G08; if it becomes material, switch to lazy per-language imports instead of the static map in `src/i18n/index.ts`.

## Out of scope
- Arabic and any other right-to-left language. Four Gulf races make Arabic the obvious next addition, but it needs mirrored layouts first — tracked as F-080.
- Translating user-generated content: league names, chat messages and team names stay as written.
- Track Limits (F-078). It follows the same pattern once this one proves it.

## Notes for whoever picks this up
- Add strings to `src/i18n/locales/en.json` only, then run `aidlc i18n sync`. Editing a non-English catalog by hand gets overwritten on the next sync and will not match the gate's placeholder check.
- `aidlc i18n status` shows coverage per language; `aidlc i18n check` is the fast local version of the gate.
- Keep placeholders identical across languages. A renamed `{{count}}` is a runtime crash, which is why the gate treats it as high severity rather than a nit.
