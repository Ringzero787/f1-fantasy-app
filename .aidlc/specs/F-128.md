# F-128 — UC: OpenF1 authenticated feed

Created: 2026-10-25 · Status: implemented, awaiting deploy · From the field, United States round,
2026-10-25: "race is over. why aren't results updating? we should nearly go live if we can."

## Goal
Undercut functions only (no app, rules or portal change). Every OpenF1 call the server makes went
out unauthenticated. OpenF1 now closes its free tier to everyone while it counts a session as live
("Global API access (including past sessions) is restricted to authenticated users until the session
ends", HTTP 401), so the results checker failed every ten minutes from the flag until OpenF1 reopened
at 22:34 UTC, 2h34m after the start, and every round this season scored two to four hours late for
the same reason. The live Moonshot sweep (F-111) would have seen the same 401 for the whole race.

The provider granted the owner a paid feed in writing on 2026-09-28 (ADR-001). The owner bought it
on 2026-10-25. Its only authentication is an OAuth2 password grant (https://openf1.org/auth.html):
POST username and password to `/token`, receive a bearer token that lives an hour, send it as
`Authorization: Bearer …`. This feature puts that token on every OpenF1 call.

## Acceptance criteria
- [x] **Credentials are Firebase secrets**, `OPENF1_USERNAME` and `OPENF1_PASSWORD`, set by the owner
      with `firebase functions:secrets:set` (never typed into a chat, a file or a commit). Every
      function that reaches api.openf1.org lists them: `checkOpenF1Results`, `checkQualifyingResults`,
      `checkSprintResults`, `syncRaceSchedules`, `monitorScheduleChanges`, `moonshotLiveSweep`
      (`openf1Secrets` in `functions/src/ingestion/openf1Auth.ts`).
- [x] **One token module** (`openf1Auth.ts`): exchanges the credentials form-encoded at the token
      URL, caches the token in the instance, renews it five minutes before OpenF1 says it expires
      (an hour when `expires_in` is missing; half-life for a token under ten minutes), makes one
      exchange at a time per instance, and forgets it on demand. A refused, malformed or failed
      exchange is not retried for a minute. Tests: `functions/test/openf1Auth.test.js` (exchange,
      reuse, renewal at 56 min not 54, short lifetime, concurrent callers share one exchange,
      refused / malformed / failed exchange, the minute's cool-down, forget).
- [x] **Every OpenF1 call carries it** through one `openf1Fetch`: `fetchApi` in `openf1Client.ts`
      (sessions, session results, drivers, laps, starting grid, and the 429 retry) and
      `fetchPositions` in `moonshot/liveSweep.ts`. A 401 that arrives with a token renews it and
      retries once; a second 401 is the same error as before, not a loop (tests on `openf1Fetch`,
      on the client's 401 path and on the 429 retry carrying the renewed token). A test loads the
      compiled functions and asserts all six bind both secrets.
- [x] **Never worse than before.** No credentials bound (a test, the emulator, a script, a function
      that does not list the secrets): the call goes out unauthenticated exactly as it did before
      F-128, with one warning per instance (the environment is checked before the secret is read,
      so the SDK's own per-read warning does not fire either). Credentials bound but refused (4xx):
      the same fallback, logged as an **error** once a minute, since in production that is a wrong
      password or a lapsed feed. No request body or provider response body is ever logged, not even
      through a JSON parse error's message.
- [x] **Rate limits respected.** The paid tier allows 6 requests a second and 60 a minute; the
      client keeps its 400 ms spacing (at most 2.5 a second) and the sweep makes one call a minute.
- [x] `npm --prefix functions run build` clean; `node --test functions/test/*.test.js` passes with
      the 9 new tests.

## Data
No user data. The credentials belong to the studio's OpenF1 account and live in Secret Manager. The
provider's terms: paid feed granted for this use on 2026-09-28 (ADR-001); the owner is asked to
restate the in-app Moonshot surface to the provider as ADR-001's 2026-10-07 note requires, which is
not a condition of this deploy but is of the live-timing switch.

## Performance budget
One token exchange per instance per hour, which for scheduled functions that scale to zero means
about one per run. Nothing per request beyond a header. Worst case per call under failure: two
token exchanges and three GETs, bounded, inside the feed's 6 a second and 60 a minute.

## Deploy
1. Owner sets both secrets (done before the deploy or the deploy fails on the missing secret).
2. `functions-deploy` op with `only` naming the six functions above.
3. Verify on the next session: the checker's log shows `Fetching:` without `401` while OpenF1's
   anonymous endpoint still answers 401 (the live window), or simply results landing within one
   ten-minute tick of the classification.
4. Separately: `uc-script` op with `setMoonshotConfig.js` (`DESIRED.liveTiming` is already true),
   which starts the live sweep and the race-day card (F-111). Raised only once the owner has the
   provider's written confirmation that the arrangement covers the in-app live positions card
   (ADR-001, notes of 2026-10-07 and 2026-10-25), not on the owner's go alone.

## Out of scope
- MQTT / WebSocket streaming (the sweep's one call a minute is enough for a positions card).
- Moving the Pit Wall worker's ingest onto the token (it has its own arrangement under ADR-001 and
  its own code base; follow-up if its reads ever hit the live-window 401).
- Scoring earlier than the classification: the checker still waits for OpenF1's `session_result`,
  which appears at the flag; the token only stops the lockout.
