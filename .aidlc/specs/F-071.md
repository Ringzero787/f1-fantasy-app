# F-071 — UC: Pit Wall news wire: read, rate and learn

Created: 2026-09-19 · Revised: 2026-09-25 · Status: building

## Goal
Undercut (root app). The super fan wants to know what happened and what it means for their team in five minutes. The wire is fed from the app's own `articles` collection (F-070 first cut). This feature makes it the reader's: headlines they have read leave the Briefing and the next ones take their place, a thumb either way teaches the page what they want more or less of, and nothing is curated by hand. The owner decided on 2026-09-25 not to tag stories for distribution; readers do it.

## Acceptance criteria
- [ ] The worker publishes the last thirty headlines in the seven-day window (ranked as in F-070) rather than eight, so there is a backlog for the next ten to come from as the reader marks them read.
- [ ] The Briefing shows the ten highest-ranked unread headlines (five on a phone, with a line saying how many more are on the Wire); the Wire page shows all of them, read ones dimmed and hideable. "You are caught up" when nothing is unread.
- [ ] Each headline carries three controls with accessible names: mark read (it leaves the Briefing at once), more like this, less like this. A thumb pressed again clears it. The controls never open the driver panel the rest of the row opens.
- [ ] Taste is learned from thumbs: +1/-1 on the story's entity and on its kind. Ranking is the worker's editorial order plus twice the personal score, so taste moves a story a step or two and never hides what happened; a thumbs-down demotes, it does not remove.
- [ ] A reader's history is one private document, `users/{uid}/pitwall/wire` `{read, liked, updatedAt}`, readable and writable by the owner only; the rules refuse any other key and require both maps, and a rules test proves a stranger cannot read it. Read history is capped at 400 keys so the document stays small.
- [ ] Story keys are a hash of the link (falling back to the headline), so retitled stories keep their marks and keys are safe as document fields.
- [ ] A failed read or write of the history is silent: the page keeps working, a lost mark is not an error in the reader's face.
- [ ] Pure ranking, marking and rating logic is unit-tested (`web/pitwall/src/data/wire.test.ts`); the scroll budget still passes with the controls on the page.

## Targets
- forge worker (the wire's window, and the outlooks job)
- firebase (rules)
- web

## Data
**Per reader:** which story keys they marked read or rated, and when. Owner-only, stays in Firestore, no third party, never sent to a model.

**To the model, for the Outlook:** published, non-personal facts about one driver — the projection, the price model, circuit fit, this season's classifications, the session forecast, and the headlines already tagged to that driver or team. Nothing about the reader, no account data, nothing from anyone's team. It leaves this machine only as that prompt, through the Claude Code CLI on the studio's own subscription (`PW_LLM=api` sends it to the Anthropic Messages API instead, for a runner with no CLI session). Nothing is kept here beyond the stored text and the token counts on the run record.

## Performance budget
Reader history: one document read on sign-in, one write per mark.

Outlook: one `briefing` job a day, five minutes after the daily `projections` job, writing the twelve highest-projected drivers — about 450k tokens a day through the CLI, where one call costs roughly 36k because it carries the agent runtime's own prompt (the same question on the API costs about 1k). That overhead is the price of not holding a second metered account, and it is why the ceiling counts cache tokens: on a subscription the limit is the point, not a bill.

The cost is bounded rather than estimated: a driver limit (`PW_OUTLOOK_LIMIT`, twelve by default), a token ceiling (`PW_OUTLOOK_MAX_TOKENS`), a wall-clock deadline so the job cannot hold the single worker slot all afternoon, and a resume that leaves alone any driver already written for the published payload — so the retries a failed job attracts do not pay for the same text five times.

## Out of scope (moved to a later feature)
- Wider source ingestion, clustering across outlets, the daily LLM briefing, admin review queue.
- Social media ingestion; audio/video summaries.
- Cross-reader learning: taste is per reader only.

## Outlook (added 2026-09-27)

- [ ] One written outlook, three sentences at most, for **the twelve highest-projected drivers**, generated **once a day** (a `briefing` job five minutes after the daily `projections` job) from the PUBLISHED payload only: projection, price model, circuit fit, splits, this season's classifications, the session forecast and the tagged headlines. Twelve and daily, not the whole grid after every session, because a call through the CLI carries the agent's own runtime prompt and the prose is about the round rather than the session. Stored in `pw_entities/{season}_{round}_{driverId}`; pass holders only (existing rule).
- [ ] The model sits behind one interface (`workers/pitwall/src/model/llm.ts`, default `claude-sonnet-5`) with two doors: **`cli`** by default — the Claude Code CLI on this machine, on the studio's own subscription, with no key at all — and **`api`** when `PW_LLM=api`, the Anthropic Messages API with a key, for a runner that has no CLI session. The CLI is called with our own system prompt, no tools, no MCP servers and none of the operator's settings, so nothing in a headline can reach a hook.
- [ ] A validation pass refuses the text unless every part of it came from the inputs. Refused: a number not among the inputs' numeric fields, in digits or spelled out where it measures something, or attached to the wrong thing (a figure beside the word `median`, `floor` or `ceiling` must be that number); **any capitalised word — the first of a sentence included — that is not this driver, their team, their teammate, the venue or a session**, an allowlist, so an invented team principal is caught as readily as the wrong driver; **any penalty, contract, injury or crash claim at all**, because the KIND that would license one is itself derived from the headline's own words, and the spec has always said never to state an unconfirmed penalty as fact — the wire tile carries the headline and the link instead; wagering language; a quotation or a link; more than three sentences or 110 words, or fewer than 25; and a run of more than seven words shared with a headline, because our copy has to be our own words. A refused text is retried once with the reason; a second refusal stores nothing and the portal keeps its line built from the numbers.
- [ ] The portal labels it "Estimate · written by AI", lists what it was built from, and shows when it was written.
- [ ] Headlines are untrusted input: capped at 160 characters, stripped of control characters and angle brackets, and sent in a fenced HEADLINES block with a system instruction that the block is data to summarise and never instructions. Nothing in headline text grants anything — not a number, not a name, not a claim — because the point is that a headline cannot talk the model into something we then publish as our own analysis.
- [ ] Data flow: the model receives published, non-personal facts only — nothing about the reader, no account data, nothing from anyone's team. By default they leave this machine through the Claude Code CLI under the studio's own subscription, whose terms are the subscription's rather than the API's; under `PW_LLM=api` they go to the Anthropic Messages API instead. Nothing is retained on our side beyond the stored text and the token counts on the run record.
- [ ] Reaching the CLI costs the service as little sandbox as it can. The unit binds the binary read-only and exactly one file — `~/.claude/.credentials.json` — into a config directory of the worker's own, with `HOME` and `CLAUDE_CONFIG_DIR` pointed there. `~/.claude` is never mounted: it holds the maintainer's transcripts, notes and hook scripts, and a worker able to write there could have run code outside the unit. The call itself denies every tool **by name** (`--disallowed-tools`; `--allowed-tools` is an auto-approve list and restricts nothing), loads no settings, hooks or plugins (`--setting-sources ''`), takes no MCP servers and answers no permission prompt. The blast radius of a compromised worker is one revocable token.
- [ ] There is no key to hold by default: the worker calls the Claude Code CLI on this machine (`PW_CLAUDE_BIN`, resolved by the deploy op), and the systemd unit binds only that binary and its session directory through an otherwise empty home. The prompt goes in on stdin, never on a command line where `ps` would show it. Anyone choosing `PW_LLM=api` puts a key in `/data/pitwall-worker/env` by hand; that file is 0600 on every deploy and the key never appears in logs, run records or alerts.
- [ ] A model call that fails is one driver's failure: it is caught, counted, and the run carries on and still reports its counters. A run that writes nothing at all while failing raises an alert.
- [ ] `PW_OUTLOOKS=off` is the kill switch: the job completes and writes nothing. The ceiling, the deadline and the driver limit come from the environment through one pure function, so the brakes on model spend are covered by a test rather than by hope, and `PW_OUTLOOK_MAX_TOKENS=0` means zero rather than "unset".
- [ ] Web read path: the portal asks for the outlook only for a pass holder; a refused or failed read, or no document yet, shows the line built from the numbers with the label "Estimate · from the numbers", never an error.
