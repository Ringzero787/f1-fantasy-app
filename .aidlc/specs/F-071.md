# F-071 — UC: Pit Wall news wire: read, rate and learn

Created: 2026-09-19 · Revised: 2026-09-25 · Status: building

## Goal
Undercut (root app). The super fan wants to know what happened and what it means for their team in five minutes. The wire is fed from the app's own `articles` collection (F-070 first cut). This feature makes it the reader's: headlines they have read leave the Briefing and the next ones take their place, a thumb either way teaches the page what they want more or less of, and nothing is curated by hand. The owner decided on 2026-09-25 not to tag stories for distribution; readers do it.

## Acceptance criteria
- [ ] The worker publishes the last thirty headlines in the seven-day window (ranked as in F-070) rather than eight, so there is a backlog for the next ten to come from as the reader marks them read.
- [ ] The Briefing shows the ten highest-ranked unread headlines (five on a phone, with a line saying how many more are on the Wire); the Wire page shows all of them, read ones dimmed and hideable. "You are caught up" when nothing is unread.
- [ ] Each headline carries three controls with accessible names: mark read (it leaves the Briefing at once), more like this, less like this. A thumb pressed again clears it. The controls never open the driver panel the rest of the row opens.
- [ ] Taste is learned from thumbs: +1/-1 on the story's entity and on its kind. Ranking is the worker's editorial order plus twice the personal score, so taste moves a story a step or two and never hides what happened; a thumbs-down demotes, it does not remove.
- [ ] A reader's history is one private document, `users/{uid}/pitwall/wire` `{read, liked, updatedAt}`, readable and writable by the owner only; the rules refuse any other key and require both maps, and a rules test proves a stranger cannot read it. Read history is capped at 400 keys so the document stays small.
- [ ] Story keys are a hash of the link (falling back to the headline), so retitled stories keep their marks and keys are safe as document fields.
- [ ] A failed read or write of the history is silent: the page keeps working, a lost mark is not an error in the reader's face.
- [ ] Pure ranking, marking and rating logic is unit-tested (`web/pitwall/src/data/wire.test.ts`); the scroll budget still passes with the controls on the page.

## Targets
- forge worker (limit only)
- firebase (rules)
- web

## Data
Per reader: which story keys they marked read or rated, and when. Owner-only; nothing leaves Firestore; no third party. Not sent to any model.

## Performance budget
No LLM. One document read on sign-in, one write per mark.

## Out of scope (moved to a later feature)
- Wider source ingestion, clustering across outlets, LLM briefings and outlooks, admin review queue.
- Social media ingestion; audio/video summaries.
- Cross-reader learning: taste is per reader only.

## Outlook (added 2026-09-27)

- [ ] One written outlook per active driver per round, three sentences at most, generated after each projections job (`briefing` job, five minutes later) from the PUBLISHED payload only: projection, price model, circuit fit, splits, this season's classifications, the session forecast and the tagged headlines. Stored in `pw_entities/{season}_{round}_{driverId}`; pass holders only (existing rule).
- [ ] The model sits behind one interface (`workers/pitwall/src/model/llm.ts`, Anthropic Messages, default `claude-sonnet-5`), key from the worker's environment on forge.
- [ ] A validation pass refuses any text that carries a number not present in the inputs, names a driver or team that is neither this driver's, their team's, their teammate's nor named in a headline, claims a penalty/injury/contract/ban/crash no headline carries, uses wagering language, or runs past four sentences. A refused text is retried once with the reason; a second refusal stores nothing (the portal falls back to its line built from the numbers).
- [ ] The portal labels it "Estimate · written by AI", lists what it was built from, and shows when it was written.
- [ ] Headlines are untrusted input: they are capped at 160 characters, stripped of control characters, and sent in a fenced HEADLINES block with a system instruction that the block is data to summarise and never instructions. The validator's allowed numbers and names come from the structured fields only (the driver, team, teammate and the numeric facts), never from headline text; a penalty or contract claim needs a headline whose KIND tag matches, and injury or crash claims are never accepted.
- [ ] Data flow: the model receives published, non-personal facts only, over the Anthropic Messages API from the forge worker; nothing about the reader. Anthropic does not train on API traffic; no data is retained on our side beyond the stored text and token counts on the run record.
- [ ] The key lives in `/data/pitwall-worker/env` (mode 0600, written by the deploy op from the operator's environment), is read by the worker process only, and never appears in logs, run records or alerts.
- [ ] Spend is bounded, not estimated: a run generates for at most 30 drivers and stops writing once it has spent 60,000 tokens (`PW_OUTLOOK_MAX_TOKENS`); `PW_OUTLOOKS=off` in the worker env is the kill switch, under which the job completes and writes nothing. Expected use is about 1.3k tokens per driver, ~22 drivers per run, up to seven runs a round — inside the $40/month budget; token counts are reported on each run record.
- [ ] Web read path: the portal asks for the outlook only for a pass holder; a refused or failed read, or no document yet, shows the line built from the numbers with the label "Estimate · from the numbers", never an error.
