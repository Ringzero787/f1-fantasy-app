# F-041 — TL: Offered odds stay above 1.00

Created: 2026-09-11 · Status: building

## Goal
Ben's weekly lines are priced by `seedFromModelsDoc.js` as `1 / (p × 1.047)` with no cap, and `setBestBets.js` uses the same formula when it puts a replaced best bet back on its model line. A model probability above about 0.955 would price a side below 1.00 — a correct call paying back less than the stake — and a probability of 0 divides by zero. Today's bands keep probabilities well inside that range, and the line checker (F-039) would flag such odds after the fact, but nothing prevented them. Both scripts now share one capped pricing function with the same cap the functions' `_odds.ts` uses (priced probability within [0.001, 0.99]), so offered odds are always between 1.01 and 1000. The seeder is also restructured so its MODELS-doc parser can be tested. (The feature was registered as "the generator can emit exactly 1.00": it cannot — `_odds.ts` is already capped at 1.01.)

## Acceptance criteria
- [ ] `scripts/_pricing.js` `offered(p)` returns a finite value above 1.00 for every p in [0, 1]: 1.01 at p ≥ 0.99/1.047, 1000 at p = 0, 1.91 at p = 0.5.
- [ ] `seedFromModelsDoc.js` and `setBestBets.js` both price through `_pricing.js`; no other uncapped `1 / (p × HOLD)` remains in `newgame/functions/scripts/`.
- [ ] A band whose in-band probability is above 0.955 is priced 1.01, where the old formula gave less than 1.00 (unit test).
- [ ] `seedFromModelsDoc.js` exports `parseModels(md)`; unit tests on a synthetic MODELS-shaped doc cover race drivers, bold markers, zone σ, constructors doubled into SUM space, qualifying, and a missing section raising an error.
- [ ] Parsing the real `MODELS_7.md` reproduces every stored Madrid R16 model line exactly (range, σ, probabilities, odds); Ben's three best bets differ only in their deliberately set 1.90/1.90 odds.
- [ ] The seeder's dry-run output keeps its format, so the tl-lines-seed op reads the same.
