# F-111 — UC: One live-timing ingest for race day, fanned out through Firestore

Created: 2026-10-07 · Status: building · Design source: the owner's ask of 2026-10-07 ("how can we make live timing work? something more decentralised") on F-108 §17

## Goal
Undercut (root app) and Pit Wall. F-108's race-day card had every device poll the timing provider itself, so it shipped switched off: the data arrangement (ADR-001) covers the Pit Wall ingest, not the whole audience. This replaces that with one ingest and many readers: a scheduled server sweep pulls positions once a minute while a race is in its window and writes a small document under the race; the app and the portal listen to that document. The provider sees one request a minute whatever the audience, clients get pushed updates instead of polling, and the same document can feed every other race-day surface later.

## Acceptance criteria
- [ ] **The sweep.** `moonshotLiveSweep` (scheduled, every minute) finds the race in its live window — `in_progress`, or within three hours of its scheduled start (six when the server still says in progress) — and, for it, resolves the OpenF1 race session by UTC day (reusing F-108's `sessionForRace` rule server-side), fetches `/position`, keeps the latest position per car, maps car numbers to driver ids through the ingestion client's table, and writes `races/{raceId}/live/positions` = `{ raceId, sessionKey, at, byDriver: { [driverId]: position }, source: 'openf1' }`. It reads `config/app.moonshot.liveTiming` first and does nothing while it is off — the switch stops the pull, not only the rendering. With no race live it does one query (season + status + round, the account header's index) and exits; with no session or a feed error it leaves the last document in place and logs; the provider call has a 15-second timeout and only numeric car numbers and positions become keys and values. Pure helpers (`isLive`, `sessionForRace`, `latestByDriver`) with tests, and the sweep itself driven through a stubbed database and feed. The window opens half an hour before the start: `in_progress` alone never opens it, because the lock sweep sets that on Friday.
- [ ] **Readers.** The app's `useMoonshotLive` subscribes to `races/{raceId}/live/positions` when `config/app.moonshot.liveTiming` is on and the race window is open; it no longer calls the provider from the device. The portal's "Your Moonshot" tile shows the called driver's current position and the IN / OUT / ONE POSITION AWAY / PENDING state from the same document. Rules: `races/{raceId}/live/{docId}` readable by any signed-in user, never client-writable.
- [ ] **The switch's meaning.** `liveTiming: true` now means "the server pulls live positions and the clients render them"; off means no pull and no card — so turning it on or off is a config write with no build. ADR-001 gains a dated note naming F-111 as a second consumer of the timing feed (one server pull a minute on race day, a free surface, never pass-gated) and recording that the owner confirms the arrangement covers the app surface before switching it on. Documented in F-108's spec and the enable script.
- [ ] Deploys through `aidlc op functions-deploy` (`functions:moonshotLiveSweep`) and `rules-deploy`; the app change ships with the next store build; the portal with `pitwall-pages-deploy`.

## Targets
- firebase (functions, rules)
- android, ios, amazon (the card reads the document)
- web (the tile reads the document)

## Data
New subcollection `races/{raceId}/live` with one document, `positions`, rewritten each minute during a race (~180 writes per race); read by every signed-in client on race day. No personal data.

## Performance budget
Sweep: one `races` query per minute all season (two documents), plus one sessions call and one positions call per minute during a race window. Clients: one listener each.

## Out of scope
- Live scoring projections, league live standings and notifications built on the same document (candidates, see the owner's question of 2026-10-07).
- Track Limits' own settlement feed (lives in /data/tracklimits now).
