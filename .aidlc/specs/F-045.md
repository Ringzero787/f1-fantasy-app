# F-045 — UC: Faster roster edits and standings

Created: 2026-09-17 · Status: planned

## Goal

Undercut players still report that selling a driver and buying another is slow, and that the league table takes a while to appear. F-018 made driver add/remove optimistic, but each edit still cost one callable plus two follow-up team reads and a transaction log write, flipped the `isLoading` flag that the My Team screen renders as a full-screen spinner, and constructor edits had none of the optimistic treatment. The leagues tab ran the league list load (spinner on, one pending-membership check per league in series), then a league read, then a members fetch, before anything fresh showed. This change makes the roster callables return the updated team so the app adopts it without refetching, gives constructor edits the same optimistic path, removes the spinner flip from all four edits, loads the league list stale-while-revalidate with parallel pending checks, and follows standings through the existing Firestore listener so the table updates live after each race without a pull-to-refresh.

## Acceptance criteria
- [ ] `addDriverSecure`, `removeDriverSecure`, `setConstructorSecure`, `removeConstructorSecure` return `team`: the document as it reads after the write, with `id`, the written fields, and resolved `lockedPoints`/`totalPoints` where the write used increments. Existing return fields are unchanged.
- [ ] `teamService.addDriver/removeDriver/setConstructor/removeConstructor` adopt `res.data.team` when present and only fall back to `getTeamById` when it is absent (older deployed functions).
- [ ] `useTeamStore.addDriver/removeDriver/setConstructor/removeConstructor` never set `isLoading: true`; they set `isSavingRoster` for the in-flight window and adopt the returned team via `updateTeamAndSync` with no follow-up read.
- [ ] `setConstructor(id, contractLength, meta)` paints the new constructor before the callable resolves and rolls back on error; `removeConstructor` clears the slot optimistically and rolls back on error; a second constructor edit while one is in flight is ignored.
- [ ] The simple market panel passes constructor meta so the optimistic path is used.
- [ ] `loadUserLeagues` sets `isLoading: true` only when no league list is cached, and checks pending membership for all leagues in parallel.
- [ ] `subscribeToLeagueMembers(leagueId)` seeds `members` from `membersByLeague[leagueId]` (or `[]`) before the first snapshot, and each snapshot writes `members`, `membersByLeague`, `membersLastFetched` and clears `isLoading`/`isRefreshingMembers`.
- [ ] The simple league panel subscribes to the active league's standings on mount and unsubscribes on change/unmount; demo mode keeps the local members build.
- [ ] Jest: `__tests__/store/rosterAdopt.test.ts`, `__tests__/store/leagueLive.test.ts`, `__tests__/services/teamFromCallable.test.ts` pass alongside the existing suite.

## Targets
- android (app store, service, simple panels)
- functions (Undercut codebase `default`: the four roster callables)

## Data
No new user data. The callable response now carries the caller's own team document; nothing new is stored.

## Performance budget
Per roster edit: 1 callable + 1 best-effort log write (was 1 callable + 2 reads + 1 write). Leagues tab: league list from cache at once; standings from cache at once, then one listener instead of a fetch per open. Bundle +0 KB.

## Out of scope
- Cloud Functions cold-start latency (`minInstances`); the callable round-trip itself is unchanged.
- Real-time listener on the user's own team document.
- The legacy `app/(tabs)` screens beyond what shares the store.
