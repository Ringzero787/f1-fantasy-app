# F-101 — UC: the app's metadata sync no longer overwrites a newer server copy

Created: 2026-10-05 · Status: building

## Goal
Undercut (root app). The store's periodic sync (`startPeriodicSync`, every 60 s) and the rehydrate sync push every local team's metadata — `name`, `aceDriverId`, `leagueId`, avatar — to Firestore with a fresh `serverTimestamp`, without looking at the server copy. A rename made on the Pit Wall portal (F-100) or on another device is therefore reverted within a minute of the app being open; seen on 2026-10-05 (portal rename 00:56 UTC, both teams rewritten by the app at 01:27). The server copy must win whenever it is newer than this device's.

## Acceptance criteria
- [ ] `syncTeam` reads the team document first and skips the write when the server's `updatedAt` is newer than the local one (`serverIsNewer` in `src/utils/syncFreshness.ts`). A missing document is skipped as before.
- [ ] `toMillis` reads every shape `updatedAt` takes on the client: live Firestore Timestamp, the persisted `{ seconds, nanoseconds }` / `{ _seconds, _nanoseconds }` object, Date, number, ISO string; unreadable local time counts as stale, unreadable server time as unknown (no skip). Unit-tested.
- [ ] Local edits that the sync is meant to carry (ace, league assignment, avatar, name) still reach the server: each stamps `updatedAt` locally when it changes the team, or writes directly, so the newer-check does not swallow them. Verified by reading each path; any path found not stamping is fixed in this feature.
- [ ] Rules unchanged; no new server code. The existing jest suite passes.
- [ ] Ships with the next Undercut store build; until then a web rename is reverted by any running copy of the app.

## Targets
- android
- ios
- amazon

## Data
No new user data; one extra document read per synced team per sync.

## Performance budget
One `getDoc` per team per sync tick (two teams, once a minute while the app is open).

## Out of scope
- Replacing the periodic sync with explicit writes per edit (the right end state; a larger change).
- Moving the app's own rename onto the `renameTeam` callable (F-100 follow-up).
