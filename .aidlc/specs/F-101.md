# F-101 — UC: the app's metadata sync no longer overwrites a newer server copy

Created: 2026-10-05 · Status: building

## Goal
Undercut (root app). The store's periodic sync (`startPeriodicSync`, every 60 s), the rehydrate sync and the post-load sync pushed every local team's metadata — `name`, `aceDriverId`, `leagueId`, avatar — to Firestore with a fresh `serverTimestamp`, whether or not this device had changed anything. A rename made on the Pit Wall portal (F-100) or on another device was therefore reverted within a minute of the app being open; seen on 2026-10-05 (portal rename 00:56 UTC, both teams rewritten by the app at 01:27). The sync must write only what this device changed, and nothing when it changed nothing.

## Assumptions
- No clock comparison: device clocks are not trusted, and after a restart the store's rehydrate step replaces a persisted timestamp with the launch time, so `updatedAt` cannot tell a stale copy from a fresh one.

## Acceptance criteria
- [ ] `FantasyTeam.dirtyKeys` (client-only) records the metadata fields changed on this device since the last push. `syncTeam` writes only `dirtyKeys ∩ METADATA_SYNC_KEYS` (`name`, `avatarUrl`, `aceDriverId`, `aceConstructorId`, `leagueId`) plus `updatedAt`, and writes nothing — no read, no write — when there are none. A copy rehydrated from storage that nobody edited therefore cannot revert a rename, and an ace change cannot carry a stale name. `dirtyKeys` itself is never written.
- [ ] Every local metadata edit marks its keys: `setAce`, `setAceConstructor`, `clearAce` (ace fields), `assignTeamToLeague`, the League Manager's detach and the orphan-league prune (`leagueId`), the avatar generators in `app/(tabs)/my-team` (`avatarUrl`). The app's own rename writes directly and is unchanged.
- [ ] After a successful push the pushed keys are cleared on that team in the store (`forgetPushed`), from every caller: the immediate push after an edit, the periodic sync, the full sync and the post-load sync.
- [ ] Unit tests cover `markDirty`, `dirtyMetadataKeys`, `clearDirty` and that no server-owned field is ever a sync key. `tsc` and the full jest suite pass.
- [ ] Rules unchanged; no new server code; no new reads. Line endings of the touched files are preserved (`team.store.ts`, `team.service.ts` are CRLF).

## Targets
- android
- ios
- amazon

## Data
No new user data. The sync now writes less: only fields this device changed.

## Performance budget
Fewer writes (none on an unchanged team, where before there was one per team per minute); no added reads.

## Out of scope
- Moving the app's own rename onto the `renameTeam` callable (F-100 follow-up).
- Ships with the next Undercut store build; until then any running copy of the app reverts a web rename within a minute.
