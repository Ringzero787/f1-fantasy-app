# F-038 — Repo: Production operations via aidlc op

Created: 2026-09-11 · Status: building

## Goal
Every change to live data or Firebase infrastructure for Undercut and Track Limits goes through `aidlc op` instead of ad-hoc commands: weekly line seeding, best bets, repair and backfill scripts, and rules, index, storage and functions deploys. Each becomes an `OP-###` record — dry-run, backup, G14/G15 gates, apply, verify, rollback — that wraps the scripts the project already uses. Logs and backups go to the SMB share, never this public repo. For the operator (the user, or a Claude session), updating a weekend's odds becomes `aidlc op new tl-best-bets …` → `dryrun` → `apply`, with a restorable backup and Ben's odds checker (F-039) run before and after.

## Acceptance criteria
- [ ] `aidlc op kinds` lists rules-deploy, indexes-deploy, storage-rules-deploy, functions-deploy, tl-functions-deploy, tl-lines-seed, tl-lines-seed-sprint, tl-best-bets, uc-script and tl-script, with target project f1-app-18077.
- [ ] `aidlc op dryrun` on a tl-best-bets operation prints the before → after table and writes nothing to Firestore.
- [ ] `aidlc op apply` is refused by G14 when the operation has no successful dry-run, when its parameters changed since that dry-run, and, for a deploy kind, when HEAD is not on origin/master.
- [ ] `aidlc op apply` on a data kind writes `/mnt/smb/f1-app/aidlc-ops/OP-###/backup.json` before any Firestore write; `firestore-restore.js --from=<that file>` lists the documents it would restore, and `--write` overwrites them (or deletes ones that did not exist).
- [ ] `scripts/ops/firebase-deploy.sh` leaves the pre-existing ADC file in place after a successful deploy and after a failed one.
- [ ] `setBestBets.js` stores calls as: driver O4.5 → 5–22, driver U5.5 → 1–5, constructor P2-P5 → 4–10, constructor O12.5 → 26–44, constructor U17.5 → 3–34; it refuses once the race has locked; unit tests cover the conversions.
- [ ] The operations done before this existed are recorded: OP-001 (Madrid best bets), OP-002 (Madrid manualLine lock), OP-003 (F-037 functions deploy).
- [ ] No backup or log file is written inside the repository.

## Targets
- backend: Firestore data, Firestore/Storage rules, indexes, and Cloud Functions for both codebases (`default`, `tracklimits`).
- tooling: operator scripts on the Linux build box (`scripts/ops/`, `newgame/functions/scripts/setBestBets.js`). No app build changes.

## Data
Backups copy the Firestore documents an operation touches. For Track Limits lines that is odds data only; Undercut repairs can include user team documents (user ids, team names, rosters). Backups and logs are stored only on the private SMB share (`/mnt/smb/f1-app/aidlc-ops`) and never committed; the op records in git hold commands, exit codes and hashes.
