# F-175 — UC: Charter, Pit Wall for every player in one league

Created: 2026-11-24 · Status: building

## Goal
A second product beside the Pit Wall Pass. **Charter**, `pitwall.charter.season`, $39.99, charters one league for one season: every approved member reads paid Pit Wall while they remain in that league, the league is League Pro until the charter ends, and chartered leagues rank above other public leagues in search, lifted by weekly Rank Ups.

The full build plan, with its closed product decisions, copy and order of work, is `docs/design/charter/BUILD.md`. Its last section, "Checked against the code (2026-11-24)", lists where the plan and the code disagree. The decision is ADR-004 (`.aidlc/decisions/ADR-004-charter.md`). This feature supersedes F-060 and F-061.

The work lands as five slices on `feat/F-175-charter` (BUILD.md, "Order of work"). Only the criteria slice 1 delivers are ticked.

## Acceptance criteria

### Slice 1: ADR, types, rules, pure helpers, tests (this branch so far)
- [x] ADR-004 records Charter as a second product; ADR-001 is not edited.
- [x] Pure, unit-tested helpers in `functions/src/charter/rankUp.ts`: `weekId(utcMs)` ("YYYY-Www", ISO week, Monday 00:00 UTC), `climb(count)` (`min(count, 3)`, 0 for count ≤ 0), `rankUpsThisWeek(league, now)` (`rankUpsWeek.count` only when `rankUpsWeek.weekId === weekId(now)`), `orderChartered(leagues, now)` (chartered by `searchPoints` desc then id asc, each moved up its climb top-down; then unchartered public leagues by `memberCount` desc).
- [x] Charter state helpers in `functions/src/charter/charter.ts`: `charterActive(league, now)`, `charterAccessExpiry(user, now)`, `claimExpiry(pass, charterAccess, now)`, `charterEnabled(appConfig)` (true only for `config/app.charter.enabled === true`; the flag defaults to false and nothing sells yet).
- [x] `onUserPassWritten` restamps the claim when `pass` OR `charterAccess` changes; `stampClaim` takes `claimExpiry(...)` and deletes `pw` only when both are absent or expired. The claim shape (`pw` = epoch seconds) is unchanged.
- [x] Types: `charter`, `chartered`, `searchPoints`, `rankUpsWeek` on the app `League`; `charterAccess` on the app `User`; the same shapes exported from `functions/src/charter/charter.ts`.
- [x] `firestore.rules`: league create denies the four charter fields (absent only); a league update by anyone denies changes to them; while `charter.expiresAt > request.time` an update may not set `isPublic` or `settings.requireApproval` to anything but `true`, or remove them; users may not create or update `charterAccess`; `leagues/{id}/rankUps/{id}` has no client writes and is readable by approved members and the owner.
- [x] Tests: `functions/test/charter.test.js` (week boundary Sunday→Monday UTC and the 2026→2027 ISO year with week 53; `climb` at 0, 3, 22; `orderChartered` with two climbers, a points tie and a stale week; the claim kept when the pass goes and charter access remains, dropped when both are gone or expired) and the F-175 block in `rules-tests/firestore.rules.test.js`. The existing rules tests, including the owner `maxMembers: 42` case, still pass.

## Targets
- Undercut (repo root). Slice 1: `functions/` (`charter/charter.ts`, `charter/rankUp.ts`, `pitwall/passStore.ts`, `pitwall/index.ts`, `pitwall/pass.ts` comment only), `firestore.rules` (shared with Track Limits; no `tl_*` rule changed), `src/types/index.ts`. No UI, no purchase path, no email.
- Deploy: the rules and the `pw` functions group, through `aidlc op`, when the owner decides. Slice 1 changes no client behaviour: no client writes these fields today.

## Data
- `leagues/{id}.charter = { season, expiresAt, buyerId, source: 'stripe'|'play'|'apple', ref, purchasedAt }`, `chartered`, `searchPoints`, `rankUpsWeek = { weekId, count }`: server-written only.
- `leagues/{id}/rankUps/{weekId}_{fromUid}`: server-written only.
- `users/{uid}.charterAccess = { leagues: { [leagueId]: expiresAt } }`: server-written only. It holds league ids and dates, no new personal data.
- The `pw` custom claim: unchanged shape, now the later of the pass and charter access.
- `config/app.charter.enabled`: admin-only write (existing `config` rule), default absent = off.

## Out of scope
- Anything BUILD.md lists under "Do not build" (weekend pass, standalone League Pro, capacity pack, Amazon IAP, marketing assets).
- Restoring `allow read: if hasPass()` on the paid collections and flipping `config/app.charter.enabled`: the 50-rating flip, a separate change.
- Changing the `maxMembers` rule or the `league.expansion` product (see the open question below).
