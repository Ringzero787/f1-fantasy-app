# F-108 — UC: Moonshot in the app

Created: 2026-10-06 · Status: implemented · Design source: `docs/design/moonshot/SPEC.md` §2, §5, §8, §11–§13, §16, §17, §20, §21, §32, §34

## Goal
Undercut (root app). The whole player experience: a locked teaser before midseason, a Moonshot tab on the driver tile sheet, the quote → confirm flow in the game's own words, the declaration in the league feed, the live card on race day, and the one-time coach marks. Understandable in seconds: Driver · Prediction · Chance · Risk · Reward.

## Delivery
Two PRs. **PR 1 (this build):** config gating, the tile-sheet row (teaser before unlock), the flow sheet, the Team-screen card with Cancel before lock, the standings and race-leaderboard column, the copy table with its terminology test, and a `moonshotMenu` callable (F-106 shape) so the sheet opens with one round-trip. In PR 1 the row is reached from roster tiles only, so every PR-1 Moonshot is a Double Down; the design's primary case (any driver on the entry list, from the picker) and EXACT FINISH (when enabled) are PR 2's. **PR 2 (this build):** picker entry for non-roster drivers (a 🚀 on every driver row of the picker while a call is open), EXACT FINISH when `predictionTypesEnabled` has it (a position grid; the quote prices the position), the league feed on the LEAGUE tab (this race's locked declarations through a new `moonshotLeagueBoard` callable — decided on the server clock so no client list query on `moonshots` is needed — plus the season's `activity` history), the race-day live card (positions from the OpenF1 feed — which only the admin screens used before — read from `races/{raceId}/live/positions`, which one server sweep writes each minute while the race window is open (F-111; the device asks nobody but Firestore) **and rendered only when `config/app.moonshot.liveTiming` is on** — the switch now means "show the server's live feed"; off, the card shows PENDING and settles from the official result. IN / OUT / ONE POSITION AWAY / PENDING, then the settled line; league-mates' locked calls beneath; the window closes three hours after the start, six if the server still says in progress), coach marks (four cards, once per account via `users/{uid}.moonshotTutorialSeen`, re-opened from the sheet's ⓘ), analytics (a thin `track()` — Firebase Analytics on the web build, no-op on native until the native module is adopted; every SPEC §32 client event is fired), demo-mode fixtures so screenshots and web verification can walk the flow without a model or config. The deeper model view (circuit performance, form, qualifying projection, confidence) needs data only the Pit Wall holds → F-109.

## Acceptance criteria
- [ ] **Before unlock**: the tile sheet shows a locked Moonshot row with the configured copy ("MOONSHOTS UNLOCK AT MIDSEASON …"). Nothing else renders when `config/app.moonshot.enabled` is false or the round is before `unlockRound`.
- [ ] **Entry**: the tile detail sheet (F-058) gains a 🚀 MOONSHOT row (the sheet has no tab bar; the row sits under the Pit Wall block and opens the Moonshot sheet) for any driver on the roster — a driver not on the roster is reached from the picker in PR 2 — showing tokens left ("YOU HAVE 2 MOONSHOTS") and, if one is already called this race, that call instead of a new one.
- [ ] **Flow** (three screens, no slider): currency (`🏆 CHAMPIONSHIP POINTS · Move up the standings` / `💰 CASH · Build a stronger roster`), prediction (TOP 5 / PODIUM / WIN, each with model chance and reward from the server quote; EXACT FINISH only when enabled), stake (the three configured levels labelled CAUTIOUS / BOLD / ALL-IN), then confirmation showing exactly `HIT +X · MISS −Y` and "This Moonshot locks when race selections lock." Two taps minimum to place; a quote older than its `expiresAt` is re-fetched before confirm. Double Down framing when the driver is on the roster (SPEC §12). Every number on screen comes from the server: the prediction screen's chances and multipliers from `moonshotMenu`, the stake screen's HIT/MISS from `moonshotQuote`.
- [ ] **Before lock**: the call shows on the Team screen with Cancel (cancel returns the token; Change = cancel and call again, since one call per race is the rule and a second confirm would be refused). **After lock**: immutable, and the Change/Cancel controls disappear even if the client clock is wrong (server refusal shown as a sentence).
- [ ] **League feed**: a locked Moonshot appears to league members as the declaration in SPEC §16; hidden before lock — fixed on (the rules and the board callable always hide an open call; `hideBeforeLock` in config is informational, the client does not switch on it), and "locked" means both the call's stamped lock and the race's live lock have passed, so a declaration can never appear while its owner could still cancel.
- [ ] **Race day**: the Race Day screen shows `🚀 YOUR MOONSHOT` with the driver's current position from the live timing feed the screen already uses, and a state chip: IN / OUT / CLOSE ("ONE POSITION AWAY") / PENDING, then HIT / MISSED / VOID after settlement with the SPEC §18 copy. Also shows league-mates' locked Moonshots in a row below.
- [ ] **Coach marks**: a four-step overlay the first time the feature is available (SPEC §20), server-driven copy, shown once per account (`users/{uid}.moonshotTutorialSeen`), re-openable from an info icon on the Moonshot tab. "WHY THIS MULTIPLIER?" opens the model view of SPEC §21 from the published snapshot — predicted finish, expected finish, likely range (what the model carries); form and confidence need data only the Pit Wall holds and are F-109's.
- [ ] **Terminology**: only the words in the SPEC summary; a unit test on the copy table fails on any of the forbidden ones. Watchlist terms appear only in descriptive event names.
- [ ] **Analytics**: every client event in SPEC §32 fired through `src/services/analytics.service.ts` (`track`): opened, currency/prediction/stake selected, quote viewed, confirmed, cancelled, live viewed, model details viewed, tutorial viewed. Delivered to Firebase Analytics on the web build with storage consent **denied by default** (no consent flow exists; nothing is measured until one does and the store/privacy declaration is updated — a privacy read, not this feature's call); a no-op on native builds until the native Analytics module is adopted. The server's structured logs are the record meanwhile. `moonshot_driver_selected` fires from both entry points (tile row, picker). The app has no client analytics path today (no Firebase Analytics, no event service); `moonshot_confirmed`/`moonshot_cancelled` are structured function logs (F-106) and the rest is PR 2's, which decides the path.
- [ ] Verified on Expo web (dark and light) with screenshots in `docs/design/grid/verify/F-108-*.png` — done 2026-10-07 in demo mode (coach marks 1–4, empty team, picker with 🚀 rows, currency, prediction, why-this-multiplier, stake, confirm, called, team card, current call), both themes — and on a device build before release. Not in the demo walk: the live card (needs a race in progress, live timing on), the league feed (needs a league) and EXACT FINISH (off in the demo config, as in V1).

## Data
Writes nothing directly: all calls go through the F-106 callables. Reads `moonshots` (own, and league-mates' after lock) and the published snapshot. One per-user flag for the tutorial.

## Follow-up 2026-10-09: two faults on iPhone
Seen while checking the sheet on the iOS simulator for 2.5.2, and present since the sheet shipped
(`docs/design/grid/verify/F-108-ios-moonshot-sheet-before.png`, `…-after.png`, `…-after-xxl.png`).
- The header row was wider than the sheet, so CLOSE was clipped at the right edge. It happened at
  the default size on a nine-letter race name, so on most races. The row now wraps: when the title
  and the two buttons do not fit side by side the buttons drop to their own line, right-aligned.
  Nothing is capped or truncated, so the same holds at larger display sizes (the first cut kept
  one row and squeezed the title, which the local review showed collapsing at XL and above).
- The driver's name rendered a few points high the first time the sheet opened and was the right
  size from the next step on. Observed, not explained: removing `adjustsFontSizeToFit` from that
  Text cures it, and the same props on the tile sheet's name do not show it. The name is no longer
  fitted or capped; a long one wraps.
Checked on the iOS simulator (Release build, demo data) at display size M and XXL; at XXL the
name wraps to two lines at full size. Not checked: Android, and a phone narrower than 402pt. No
render test covers the sheet.

## Follow-up 2026-10-09: two layouts at the largest display size
Seen at XXL while checking the header fix above (`docs/design/grid/verify/F-108-ios-xxl-*.png`).
- **The team name on the Team screen was cut to its first word.** It is a single-line text field,
  and a name too wide for the line lost everything after the last word that fit — at XXL that was
  a twelve-letter name, and a 30-letter name does not fit at any size. The field is now multiline,
  so the name wraps. Return still commits (no line break can be typed or pasted in), spelling marks
  are off, and the field remounts when the display size changes, because iOS otherwise kept the
  one-line height until the app restarted.
- **A Moonshot choice card broke its label inside a word** ("CHAMP / IONSHI / P"): the value
  beside it left the label column narrower than the word. Above display size L the value now goes
  under the label, the same threshold the picker and the profile use to restack. At S, M and L
  the card is unchanged.
Checked on the iOS simulator (Release build, demo data): the name at M and XXL, after switching
size without a restart, and editing it at XXL; the cards at XXL on the currency and prediction
steps. Not checked on iOS: the cards at M after this change (the code path is the old one).
Checked on the Android emulator (release APK, demo data) at M: a long name wraps to three lines
and return commits it without a line break (`F-108-android-team-name-long.png`). `scrollEnabled`
and `spellCheck` are iOS-only props and do nothing there. Not checked: Android at XXL, Fire OS,
and the Moonshot cards on Android.
Known and left: if the display size could change while the field is focused the remount would
drop the edit.
Fixed after: return ran the save twice (on submit, then on blur), as it had before the field
became multiline, and outside demo mode both writes went through because the first had not landed
when the second compared names. The name is saved on blur only. Checked on the iOS simulator
(return saves; tapping away saves) and the Android emulator (return saves). On Android tapping a
tile does not blur the field, so that edit is not saved until the field loses focus, as before.

## Follow-up 2026-10-09: the rest of what broke at XXL
Before and after for each in `docs/design/grid/verify/F-108-ios-xxl-{signin,stats,feed}-*.png`.
- **Sign-in wordmark** broke as "UNDERC / UT". Its size is now the largest that fits the row, up
  to the scaled size (`fitFontSize` in `src/simple/grid/fitText.ts`, unit-tested). By calculation
  from the width measured on the simulator, with about 5% to spare, that is one line at every
  display size down to a 320-wide phone, and at a larger system text size (the row is divided by
  the font scale). If the estimate is ever short the name clips by a sliver, not to an ellipsis.
  Not `adjustsFontSizeToFit`: that leaves the tracking at the unshrunk value, and this face's
  tight negative tracking then overlaps.
- **Sign-in buttons**: the labels ran past the pill. They shrink to stay on one line inside it,
  the way SegmentPill labels already do (down to 0.6 of their size), and the pill has side
  padding. By estimate the longest label needs about 0.67 at XXL on a 360-wide phone.
- **Season points on the Team screen** were squeezed by the two stats beside them until the
  digits overlapped (the overlap described above). Above display size L the two smaller stats go
  under the total.
- **Moonshot feed on the League tab**: the first line of every entry was clipped, from a line
  height that did not scale. Found while looking over the other screens at XXL.
Checked on the iOS simulator (Release build, demo data): sign-in at M and XXL, Team at M and XXL,
League at XXL. Checked on the Android emulator (release APK, demo data, 384dp wide) at XXL after
the review fixes: sign-in with all three buttons including Amazon (`F-108-android-xxl-signin.png`)
and the Team screen (`F-108-android-xxl-team.png`). Not checked: the review fixes on iOS (ratio,
clip, label floor), a phone narrower than 384dp, Fire OS, a larger system text size on a device,
the League feed on Android, and sizes between M and XXL. The lineup row's SHARE and LOCKED wrap onto two lines
at XXL; that is legible and was left.

## Follow-up 2026-10-09: the sign-in buttons use the providers' own artwork
Raised by the local review of the XXL fixes. The buttons had been drawn in this app's own style: a
one-colour icon-set "G", a shopping cart for Amazon, and every label in capitals in the display
face (`F-108-ios-signin-brand-before.png`). The first repair drew Google's four-colour G from
memory; the review of that found it was Google's previous logo, which the guidelines forbid by
name. Nothing is drawn now.
- **Google**: the G cut from Google's current asset bundle (`assets/signin/google-g*.png`), at the
  bundle's size relative to the button, on the guidelines' light button: white fill, #747775
  stroke, #1F1F1F "Continue with Google", their gap (12 on iOS, 10 on Android).
- **Apple on iOS**: the system button from `expo-apple-authentication` (Continue, black on light,
  white on dark, capsule). It draws itself about 4% shorter than its frame, so its frame is that
  much taller and it measures the same 48pt as the Google button beside it.
- **Apple elsewhere** (web flow): a custom button, mark and title in one colour.
- **Amazon**: Amazon's supplied gold button image at its own proportions, centred. Its page
  offers only the supplied images, so it is not a pill like the other two.
- One height for all three, a guard so a second tap cannot start a second sign-in, and the busy
  and disabled states are exposed to screen readers. Labels are sentence case in the system face.

**Where it still departs from the published rules** (read on 2026-10-09):
- Google asks for Google Sans Medium at 14/20 in a 44 or 40-high button. The face is now Google
  Sans Medium (below); the size is still 19 in a 48-high, full-width pill, kept near the Apple
  title beside it because Google also asks to be as prominent as the other options.
- Apple's custom-button rules ask for logo artwork from Apple Design Resources at button height
  and a title 43% of that height. Off iOS the mark is an Ionicons glyph and the title is 40%.
- The white Google button is used in the dark theme too, which the page does not address.
- The Amazon image has no 3x version and is narrower than the other two buttons.
This is a reading of the three pages, not approval from any provider.

Checked on the iOS simulator (light and dark; the two buttons measure 48pt each; tapping the Apple
button starts Apple's flow, which then fails there because the simulator build is unsigned) and
the Android emulator (all three buttons, light: `F-108-android-signin-brand.png`). Not checked: a
real sign-in with any provider on a device, XXL after this rework, Android dark, Fire OS, the
pressed Amazon image, and a screen reader. `src/components/SocialAuthButtons.tsx` still contains a
one-colour G but is rendered nowhere; only its helpers are imported.

## Follow-up 2026-10-09: Google Sans on the Google button; Apple's artwork not taken
- **Google Sans Medium** is the label face on the Continue with Google button. It is OFL-1.1
  (`assets/fonts/OFL-GoogleSans.txt`), subset to Latin by `scripts/design/make-google-sans-subset.sh`
  from a pinned, checksummed package (66 KB against 2 MB), embedded by the expo-font plugin like the
  other faces and registered in `app/_layout.tsx`. The three release scripts now require six
  embedded fonts, so a store build without it fails. The label renders in Google Sans in Release
  builds made from a clean prebuild on the iOS simulator and the Android emulator
  (`F-108-ios-signin-google-sans.png`, `F-108-android-signin-google-sans.png`); the screenshots do
  not show whether the face came from the embedded copy or the bundled asset `useFonts` loads. On
  Android the label sat about 4dp high until font padding was turned off; it now measures centred.
  The licence file carries the copyright line the package's copy omits. Fonts ship without their
  licence text inside the app itself, as Archivo and JetBrains Mono already did. A label in a
  script outside Latin would fall back to the system face; there is none today.
- **Apple's logo artwork was not added.** The download from Apple Design Resources is under
  Apple's Developer Artwork License Agreement for Sign in with Apple, which has to be accepted by
  an Apple Developer Program member and says the artwork may not be "distributed, or repackaged"
  or separated from its bundle "on a standalone basis". This repository is public, so committing
  the file would publish it. Nothing was accepted or kept; the off-iOS Apple button still uses the
  Ionicons glyph. Taking the artwork means the owner accepting the licence and the file living
  outside the repo, as the keystore and Firebase config do.
