# F-029 — UC: Per-race roster and ace snapshots

Created: 2026-09-11 · Spec written 2026-09-19 · Status: building

## Goal
Undercut (root app). A team document only holds its current roster and running totals, so nothing records what a team actually fielded in a given race: `pointsHistory` is empty, past Aces are overwritten, and departed drivers fold into `lockedPoints`. That blocks an exact per-race league leaderboard (F-062) and, later, hindsight and decision-quality frames in Pit Wall. From the next scored session on, the server keeps one snapshot per team per race weekend.

## Acceptance criteria
- [ ] When qualifying, a sprint or a race is scored for a team, the server writes `fantasyTeams/{teamId}/raceSnapshots/{raceId}` (merge): `teamId`, `userId`, `leagueId`, `raceId`, `season`, `round`, the roster as fielded (driver ids with constructor, purchase price, contract length, races held and the reserve-pick flag; constructor; `aceDriverId`, `aceConstructorId`; budget), and under `phases.<qualifying|sprint|race>` the team's points for that phase, points per entity, any stale-roster penalty and `scoredAt`.
- [ ] A team that the idempotency guard skips (already in `scoredRaces`) writes nothing, so a repeated scoring run leaves the snapshot unchanged (unit-tested). The weekend total is derived by summing phases; nothing is incremented.
- [ ] The snapshot builder is a pure function in `functions/src/scoring/raceSnapshots.ts` with `node --test` coverage: roster capture, Ace capture, per-phase merge shape, missing constructor, non-finite values coerced to 0.
- [ ] Deleting a team deletes its snapshots (`onFantasyTeamDeleted`, retried, idempotent).
- [ ] Rules: a snapshot is readable by the team's owner and by members or the owner of the team's league; no client can write one (emulator rules test).
- [ ] Scoring results are unchanged: the existing scoring tests pass and no existing field on `fantasyTeams` changes meaning.

## Targets
- firebase (functions, rules)

## Data
Derived game data only (rosters and points already visible to league members). No new personal data. Deleted with the team: the `onFantasyTeamDeleted` trigger removes the subcollection whenever a team document is deleted, including by account deletion.

## Performance budget
One extra document write per team per scored phase, in the same batched commit as the team update. No extra reads at scoring time.

## Out of scope
- Reconstructing snapshots for races scored before this ships: past Aces were never stored and the `transactions` log is client-written, starts 2026-06-17 and omits auto-fills and contract expiries. F-062's backfill writes estimates and labels them as such.
- Any app screen. F-062 is the first reader.
