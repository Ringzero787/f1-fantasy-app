# F-138 — UC: Haas seat change at Brazil (Câmara in, Ocon out)

Created: 2026-11-05 · Status: planned

## Goal

Haas dropped Ocon after Mexico City 2026 and put Rafael Câmara in the car from São Paulo
(round 22) for the rest of the season. Câmara runs car 50, the number Hirakawa carried as the
Mexico City stand-in (F-134), so the number-keyed ingestion table would credit Câmara's results
to Hirakawa. The provider's driver record for a session names who was in each car, so a car
number that has changed hands is now resolved by that name, with the current occupant as the
fallback for rows that carry only the number (grid, positions, fastest lap). In the game, Ocon
retires (document kept, `isActive: false`) and Câmara is added with a starting price through a
uc-script op; the Brazil Moonshot model is then re-seeded so the Haas row prices his seat.

## Acceptance criteria
- [ ] `SHARED_NUMBERS[50]` names both occupants; `DRIVER_NUMBER_TO_ID[50]` is `camara`;
      `31` stays `ocon` (stored results keep his number).
- [ ] `driverIdFor(n, acronym)` resolves a shared number by the session's `name_acronym`
      (`HIR` → hirakawa, `CAM` → camara), falls back to the current occupant for a bare or
      unlisted name, ignores the name on an unshared number, and is undefined for an unknown
      or non-integer number; a prototype name is never a key.
- [ ] `numberToIdFor(drivers)` is the table with each shared number resolved to whoever the
      session names. Race, sprint and qualifying conversion resolve each row through
      `driverIdForRow` with the session's entry list; a shared number whose named occupant the
      table does not list is credited to the current occupant with a warning (not a hold). The
      sprint conversion now fetches the entry list too, and carries on without it.
- [ ] The live sweep keeps the session's `numberToId` on the live document beside
      `constructorOf` (both fetched until non-empty, then kept; a document from before the map
      existed asks again) and maps positions through it;
      its `Feed` exposes `entries(sessionKey)` returning both maps.
- [ ] `functions/scripts/setDriverSeat.js` (uc-script) dry-runs by default: prints the retiring
      driver, holder counts (rosters, aces, open Moonshots), and the replacement document;
      refuses to write while anyone holds the retiring driver (roster, ace, or a Moonshot in
      CONFIRMED / LOCKED / LIVE); `--apply` sets `isActive: false`, `retiredAt` and `retiredFor`
      on the retiring document and creates the replacement with `createdAt`; a re-run keeps the
      replacement's economy fields.
- [ ] The model seeder's known-driver set is active drivers only, so a retired driver is
      neither priced nor reported missing.
- [ ] The app's name fallback table knows `hirakawa` and `camara`; the app's live number map
      has 50 → camara (next build).
- [ ] Tests cover the resolver, the session map, the live sweep through a session map and the
      updated feed stub; functions suite and the script guard suite pass.

## Targets
- binary (functions: ingestion + live sweep; ops script)
- android / ios (name fallback and live number map, next store build)

## Data
No user data. Reads `fantasyTeams` and `moonshots` to count holders of the retiring driver;
writes two `drivers` documents through the op.

## Performance budget
Sprint conversion makes one extra provider call (the entry list), already made for race and
qualifying. Live document gains one small map. App bundle +0 KB.

## Out of scope
- A sell/void path for a retired driver someone still holds (nobody holds Ocon; the script
  refuses rather than strands).
- Câmara's price beyond the starting value in DESIRED (the owner can set another before the op).
- Hirakawa as a game driver.
- Re-issuing Ben's MODELS_13 for Câmara: the Haas row is Hirakawa's prediction until Ben
  publishes a new document; the re-seed records `seats.camara = hirakawa`.
