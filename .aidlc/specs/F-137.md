# F-137 — UC: Moonshot model seed maps a stand-in onto the seat

Created: 2026-11-03 · Status: planned

## Goal

Ben's MODELS_13 (São Paulo R22) prices Hirakawa, who drives Ocon's Haas for the rest of the
season; the game has no driver record for him and still calls that seat Ocon, and settlement
already follows the car (F-110). The seeder refused to write a model naming a driver the game
does not know, which is right, but it had no way to say "that row is the seat". Now it reads
team membership from the document's constructor table and models a stand-in as the missing
regular of the same team, printing the mapping in the dry run and recording it in the model.

## Acceptance criteria
- [ ] `parseConstructorTable(markdown)` returns driver → team from the "Constructor predictions"
      table; `{}` when the document has none.
- [ ] `teamsFromResults(rows)` returns driver → constructorId from a scored race's
      `results.raceResults`, skipping rows without both.
- [ ] `seatAliases(unknown, missing, standInTeams, gameTeams)` maps each unknown table driver to
      the one missing game driver of the same team; ambiguous (two missing regulars), unknown
      team, or no missing regular on that team → no alias, so the seeder still refuses.
- [ ] The seeder places a stand-in by the constructor table first, else by the latest completed
      race before this round (the document's table lists only the top teams, so Haas is absent).
- [ ] `buildModel(rows, meta, known, aliases)` re-keys the stand-in's row onto the seat before
      the unknown/missing check and records `model.seats = { seat: standIn }`; without aliases
      the model is unchanged and has no `seats` key.
- [ ] `seedMoonshotModel.js` computes the aliases from the drivers collection's `constructorId`
      and prints one `== stand-in:` line per mapping in dry run and apply.
- [ ] Test covers both table parses, the results placement, the happy path (Hirakawa → Ocon),
      the three refusals, the top-teams-only table, and the unaliased model; the functions
      suite passes; the OP dry run for brazil_2026 prints the stand-in line and no `!!`.

## Targets
- binary (ops script + the shared `lib/moonshot/models`)

## Data
No user data. Reads `drivers` (already read) for `constructorId`, and the completed `races`
documents for the last classification when a stand-in is not placed by the document.
