# F-040 — TL: Unit test harness for settlement and odds

Created: 2026-09-11 · Status: building

## Goal
Track Limits had no tests at all, so the code that moves players' garage cash — grading picks against Ben's ranges, the win bonus, loss penalty and best-bet boost, results signatures for re-grades, and the book's pricing — could regress without anything noticing. This adds a dependency-free `node:test` suite in `newgame/functions/test/` that runs against the compiled functions, and makes it (with the operator-script tests from F-038/F-039) a blocking AIDLC hygiene check, so every PR and release proves the settlement math still holds.

## Acceptance criteria
- [ ] `npm --prefix newgame/functions run build && node --test newgame/functions/scripts/*.test.js newgame/functions/test/*.test.js` passes locally and is the blocking `hygiene.test` command in `.aidlc/aidlc.yaml`.
- [ ] Tests pin the economy constants: session weights race 1 / qualifying 0.5 / sprint 0.25, WIN_BONUS 10, LOSS_PENALTY 10, best-bet profit ×1.5, best-bet staked loss −1 point, field size 22.
- [ ] `decideOutcome` returns WITH exactly when the result is inside [predictedLo, predictedHi] with inclusive bounds; a legacy `line`-only entity settles on ±1; an entity with no range never grades WITH.
- [ ] `computePayout` is tested for a staked WITH win (stake × odds + 10), a loss (payout 0, penalty 10), a zero-stake win (10), an AGAINST best-bet win (profit ×1.5 + 10), and AGAINST best-bet losses with and without stake (−1 point only when staked).
- [ ] `buildSessionResults` fills constructor sums from the driver→constructor map and counts a missing position as 22; `sigOfResults` ignores key order and changes when any position changes.
- [ ] `offeredOddsFromFairProb` adds the 5% vig and never returns odds at or below 1.00 for any probability.
- [ ] No deployed function changes behaviour: the helpers are exported from `settleWeekend.ts` without being re-exported by `index.ts`.

## Targets
