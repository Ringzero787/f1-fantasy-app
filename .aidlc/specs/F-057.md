# F-057 — UC: Profile photo upload path matches storage rules

Created: 2026-09-18 · Status: planned

## Goal

"Choose from library" for a profile picture has been failing for every Undercut player: `uploadProfileImage` wrote to `profile-images/{id}.jpg`, which matches no rule in `storage.rules`, so the catch-all `allow read, write: if false` denied it (confirmed against the deployed ruleset, which is identical to the repo). The rules already allow the signed-in owner to write `avatars/{uid}/{type}/{fileId}` (under 5 MB, `image/*`), so the upload now targets that path. No rules or server change.

## Acceptance criteria
- [ ] `avatarStoragePath(authUid, kind, entityId, contentType)` in `src/utils/avatarPath.ts` returns `avatars/{authUid}/{kind}/{entityId}.{ext}`, strips anything outside `[A-Za-z0-9_-]` from the id and extension, and maps `jpeg` to `jpg`; jest covers the happy path and an escaping attempt.
- [ ] `uploadProfileImage` builds its path with that helper from `firebaseAuth.currentUser.uid` (so the rule's `request.auth.uid == userId` always holds) and keeps its existing signature with an optional `kind` (default `user`).
- [ ] Existing callers (`GridProfileScreen`, legacy `app/(tabs)/profile.tsx`) compile unchanged.
- [ ] `npx tsc --noEmit` and `npx jest --ci` pass.

## Data
No new user data. The same image the user picks is stored under their own `avatars/{uid}/` folder instead of a path that was always rejected.
