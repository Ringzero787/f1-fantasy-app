# F-060 — UC: League Pro entitlement and purchase verification

Created: 2026-09-18 · Status: building

## Goal
Undercut (root app). League Pro is not sold on its own. A league is Pro for the season when its owner holds a Pit Wall Pass; every member of that league gets the Pro league features, nobody else pays. Playing stays free: any league without Pro keeps standard scoring, standings and the 22-member cap. The entitlement is server-owned so it cannot be granted from a client.

## Product decisions (owner, 2026-09-19)
One premium product: **Pit Wall Pass, $14.99 per season, per user** (`pitwall.pass.season`). It includes the full Pit Wall portal and League Pro for every league the holder owns. No monthly price, no separate League Pro purchase. Playing, creating leagues and a free look at the portal (including Rate My Team and the timing-derived frames) stay free. See `.aidlc/decisions/ADR-001-pit-wall-pass-and-timing-data.md`.

## Current state (verified 2026-09-19)
- Production `purchases` collection is empty: no purchase has ever been recorded. All 13 leagues have `maxMembers` 20 or 22; none was ever expanded. Nothing needs grandfathering.
- `react-native-iap` was added in `aefadb0` and removed from `package.json` in `3ad87b6` (v2.1.0, Amazon store support). `src/store/purchase.store.ts` still lazy-`require`s it, so every build since 2.1.0 shows "In-app purchases are not available right now". In-app purchase has to be re-enabled, not just extended.
- `functions/src/purchases/validatePurchase.ts` is deployed but has never validated a real receipt. It uses Apple's deprecated `verifyReceipt` endpoint.

## Acceptance criteria
- [ ] New store product `pitwall.pass.season` ($14.99; one-time product on Play, non-renewing subscription on the App Store, so it can be bought again next season) added to `src/config/products.ts`. It is the only product.
- [ ] `validatePurchase` accepts `pitwall.pass.season`, verifies the receipt with the store, and grants the pass through the single `grantPass(uid, season, source)` server function shared with the Stripe webhook (F-068).
- [ ] League Pro is derived, never bought: `grantPass` stamps `leagues/{id}.pro = { season, via: ownerUid, grantedAt }` on every league the user owns; a trigger stamps new leagues created by a pass holder and re-evaluates on ownership transfer; pass expiry or revocation clears it (league data kept read-only).
- [ ] Store setup is recorded in the spec before build: the `pitwall.pass.season` product exists and is active in Play Console and App Store Connect, the paid-apps agreement/banking (Apple) and payments profile (Google) are complete, and the Android service account used by `validatePurchase` has the Play Console "View financial data / manage orders" permission. These are owner actions in the consoles.
- [ ] iOS validation uses the App Store Server API (signed transaction / `transactionId`), not the deprecated `verifyReceipt`; Android validation also acknowledges/consumes the purchase server-side so Play does not auto-refund it after 3 days.
- [ ] One real sandbox purchase per store (Play licence tester, Apple sandbox account) is validated end to end against the deployed function and produces a `purchases` document and the `pro` field; evidence (document ids, no tokens) noted in the PR.
- [ ] The same receipt/token cannot grant Pro twice (existing duplicate-token check covers the new product; unit-tested).
- [ ] A purchase by a user who already holds a pass for the current season is rejected before the store charge is consumed or acknowledged, with a user-readable error.
- [ ] `firestore.rules` denies any client write that adds, changes or removes `leagues/{id}.pro`; covered by a case in `rules-tests/`.
- [ ] Helper `isLeaguePro(league, season)` exists once in functions and once in the client (`src/`), and returns false when `pro.season` is not the current season.
- [ ] Admin callable/op can grant or revoke Pro for a league (refunds, comps, testing) through `aidlc op`, never a bare script.
- [ ] Functions deploy goes through `aidlc op functions-deploy`; rules through `aidlc op rules-deploy`.

## Built 2026-09-25

- Purchase library back as `expo-iap` (not `react-native-iap`, which now needs Nitro modules): one dependency, an Expo config plugin, and the Amazon flavour of the billing library selected by the same `EXPO_PUBLIC_STORE=amazon` switch that drops Google Sign-In. Ships in 2.4.0 (versionCode 60, iOS build 43).
- `pitwall.pass.season` added to `src/config/products.ts` and offered from the Profile row, but only where the server-side `pitwall` block sets `mode: iap` for that platform. Everywhere else the app carries no purchase wording at all.
- The pass is the one product the device does not grant itself. `validatePurchase` verifies the receipt, then calls the same `grantPass` the Stripe webhook uses, keyed on the purchase document id so a replayed receipt cannot extend a pass twice. The client finishes the store transaction only after the server has granted, so a failure leaves the receipt with the store to be retried rather than losing a paid pass.
- iOS verification is the App Store signed transaction (StoreKit 2 JWS), verified against a pinned Apple Root CA - G3: chain issuance and signatures, validity dates, the leaf's signature over exactly what was sent, then bundle id, product id and revocation. The deprecated `verifyReceipt` path is kept only for receipts from builds before 2.4.0. Eight tests, including a happy path over a real generated chain.
- Amazon verification added (Receipt Verification Service), which needs the receipt id and the Amazon user id the purchase carries. Its shared secret sits in the function config beside Apple's, deliberately **not** as a declared secret: firebase resolves every declared secret before it filters a deploy by target, so one missing value blocks every functions deploy.

### Still owner actions
- Create and activate `pitwall.pass.season` in all three consoles (see the release notes for this version), complete the paid-apps agreements, and set `amazon.shared_secret` in the function config.
- One sandbox purchase per store validated end to end against the deployed function.

### Deviations from the criteria above
- Android acknowledgement is the client's `finishTransaction` after the server grant, not a server-side acknowledge call. The window is one round trip, and an unfinished purchase is replayed on the next start.
- `isLeaguePro` is not added: League Pro is stamped onto the league documents by `markOwnedLeaguesPro` inside `grantPass` (F-068), so there is nothing to derive on the client.

## Targets
- firebase (functions, rules)

## Data
Adds `pro` map to league documents (season, purchaser uid, purchase id, timestamp). Purchase records already stored in `purchases`; no new personal data categories.

## Performance budget
No new reads on league load (field rides on the league document already fetched).

## Out of scope
- Any client UI (F-061).
- Amazon Appstore IAP.
- Auto-renewing subscriptions or a monthly price.
