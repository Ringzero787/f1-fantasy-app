# F-037 — TL: Seed endpoints secret out of source

Created: 2026-09-11 · Status: building

## Goal
Three Track Limits operator endpoints — `tlSeedRaces` (writes the race calendar), `tlBackfillBenLines` and `tlGenerateBenLinesLite` (write Ben's lines) — are guarded by one shared secret hardcoded in source. The repo is public, and the same key ships in the Track Limits app (Demo & debug screen) and in the humannpc.com admin page's JavaScript, so anyone can rewrite the race calendar or regenerate over the live odds. After this change only a signed-in Firebase user holding the `admin` custom claim can call them (the check `tlSettleWeekend` already uses). The shared secret stops working entirely, so there is nothing left to rotate.

## Acceptance criteria
- [ ] Each of the three endpoints returns 401 for a request without an `Authorization: Bearer` header, including one that passes the old `?key=` value.
- [ ] Each returns 401 for a malformed or invalid token, and 403 for a valid ID token whose user lacks the `admin` claim.
- [ ] With a valid admin ID token, `tlGenerateBenLinesLite?raceId=<unknown>` returns 404 (auth passed, nothing written).
- [ ] An OPTIONS preflight still returns 204 with the CORS headers, so the admin page's cross-origin calls keep working.
- [ ] `grep` for the old secret string finds nothing under `newgame/` or in the humannpc admin page source.
- [ ] The app's "Generate Ben-Lite" demo button sends the signed-in user's ID token instead of the key.
- [ ] The humannpc.com admin page's Generate button sends the Track Limits admin's ID token and succeeds for the admin account.
- [ ] `newgame` and `newgame/functions` typecheck clean.

## Targets
- android, ios: the Demo & debug screen in the Track Limits app (`newgame/app/demo.tsx`).
- backend: Cloud Functions, codebase `tracklimits` (three HTTPS functions plus the new `_adminAuth.ts` helper).
- web: the humannpc.com admin page (`admin/tracklimits-admin.js`, separate repo Ringzero787/humannpc).

## Data
No new user data. The endpoints read the caller's Firebase ID token (uid and custom claims) to authorize the request; nothing is stored or sent elsewhere.

## Performance budget
n/a — one `verifyIdToken` call per operator request; app bundle unchanged apart from a few lines in the demo screen.

## Rollout
1. Deploy the three functions (`functions:tracklimits:tlSeedRaces,tlBackfillBenLines,tlGenerateBenLinesLite`). The old key is dead from this point.
2. Deploy the admin page change; its Generate button fails with 401 between steps 1 and 2.
3. The app demo button works again for admins from the next Track Limits build; until then it fails closed.

## Out of scope
- Purging the old secret from git history — it no longer grants anything once step 1 ships.
- Narrowing CORS origins — bearer-token auth makes the wildcard safe.
- Keystore passwords committed in `newgame/plugins/withReleaseSigning.js` and `scripts/fix-android-build.sh` (separate feature).
- Hiding the Demo & debug screen from non-admin users.
