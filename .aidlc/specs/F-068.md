# F-068 — UC: Pit Wall Pass entitlement and web checkout

Created: 2026-09-19 · Status: building

## Goal
Undercut (root app). Pit Wall Pass is the one premium product: the full portal plus League Pro for the holder's leagues. Web checkout through Stripe keeps about 97% of the price and gives Amazon users a way to pay; the store IAP serves people upgrading inside the app. Playing the game stays free.

## Product decisions (owner, 2026-09-19)
One premium product: **Pit Wall Pass, $14.99 per season, per user** (`pitwall.pass.season`). It includes the full Pit Wall portal and League Pro for every league the holder owns. No monthly price, no separate League Pro purchase. Playing, creating leagues and a free look at the portal (including Rate My Team and the timing-derived frames) stay free. See `.aidlc/decisions/ADR-001-pit-wall-pass-and-timing-data.md`.

## Acceptance criteria
- [ ] One price: $14.99 per season, valid through the final round of that season, via Stripe Checkout (one-time payment). **Stripe is built first** because it can be tested end to end in test mode during the 2026 beta with no store review; the IAP path (F-060) lands with the February 2027 app release.
- [ ] Stripe webhook (signature-verified Cloud Function) writes a server-owned `users/{uid}.pass = { tier, season, expiresAt, source }`; rules deny client writes (rules test). Webhook handling is idempotent on event id.
- [ ] The same pass can be bought in the Play and iOS apps as an IAP through the F-060 validation path, writing the same field. The iOS app shows no link or wording that steers to web checkout unless current App Store rules for the storefront allow it (checked at release).
- [ ] Free look, for any signed-in user: Briefing headlines, Board median projection for the top 10, Wire headlines, the user's lineup with manual editing, a **Rate My Team** score with its single biggest weakness named, and every timing-derived frame (Pace Lab, circuit lap history, pit stops, stint degradation), which is never sold (ADR-001). Pass-only: full Board (ranges, presets, probabilities, movement), recommendation comparisons, rivals' likely moves, Lineup Lab top pick, what-if projections and optimizer, entity deep dives and Outlook, Market, Season, alerts. Locked frames show their real layout with the pass offer. Gating is enforced in Firestore rules on the payload documents, not only in the UI.
- [ ] Members of a Pro league (their commissioner holds a pass) get a one-time 7-day portal trial.
- [ ] Beta controls for testing before launch: `config/app.pitwall.beta = { uids, leagueIds }` limits who sees the in-app surfaces; an admin op grants and revokes complimentary passes (`source: 'grant'`); Stripe runs in test mode until launch.
- [ ] In-app entry and upgrade promotion, all driven by an optional `pitwall` block in `config/app` (fail-open, changeable without a build; `docs/design/pitwall/ARCHITECTURE.md` section 8): a PIT WALL row under LEAGUE in the Grid Profile screen (`Upgrade` in red for free users, `Open` for pass holders), an upgrade bottom sheet, a Team screen teaser line and a weekend recap teaser. Per-platform `mode` of `iap`, `open` or `off`; never shown before the user has a lineup, never blocks a game action, capped per round, each open tagged with `src=` for funnel measurement.
- [ ] Refund/cancel from Stripe revokes at period end; an admin op can grant or revoke a pass.
- [ ] Stripe Tax enabled before launch; terms and privacy pages updated for web payments.

## Build notes (2026-09-24)
Server half built: `pass.ts` (entitlement model), `passStore.ts` (grants, trials, revocation, expiry sweep, League Pro derivation), `stripe.ts` (checkout params, signature verification, event routing), the `pw` callables and webhook, the paywall rules, and `functions/scripts/pitwallPass.js` for beta grants.

- The paywall is enforced in Firestore rules on the payload documents: `pw_pages`, `pw_entities` and `pw_projections` need the `pw` claim; `pw_public`, `pw_public_timing` and `pw_news` need only a signed-in user. Timing-derived frames are never gated (ADR-001).
- One owner for the claim: the `onUserPassWritten` trigger stamps it from `users/{uid}.pass` whatever wrote the pass, so the claim cannot drift from the document. `passStore` touches Firestore only.
- League Pro is derived: `grantPass` marks every league the holder owns, and the rules now stop a league owner from stamping `pro` by hand.
- Caught by the integration test, not by review: the grant transaction wrote before it finished reading, which Firestore refuses. It would have failed on every Stripe webhook.

Not built here: the web checkout button and the paywall's UI states (next), the in-app Profile row and upgrade sheet (ARCHITECTURE section 8), IAP (F-060/F-061), and Stripe Tax and the terms and privacy updates, which are the owner's.
