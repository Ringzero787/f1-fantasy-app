# F-140 — UC: Pit Wall check emails the owner on FAIL

Created: 2026-11-12 · Status: building

## Goal
The twice-weekly ops check flagged the held São Paulo result as FAIL within 30 minutes but only wrote a file and a log, so nobody knew for 3 days. Email the owner when a check FAILs (deduped, daily reminder, all-clear), and run it hourly with quiet OK runs.

The owner. The Pit Wall ops check (F-132, F-135) caught the held São Paulo 2026 result as FAIL 30 minutes after the hold (2026-11-08 19:33Z) and again on 11-09 and 11-12, each time with the exact fix, but it only wrote to `/data/scripts/pitwall-check.log` and a file on the share. Nobody reads either unprompted, so 94 teams went three days without a score (F-139). After this change a FAIL emails the owner once, reminds once a day while it lasts, sends an all-clear when it resolves, and the check runs hourly (quiet when OK) so the first email lands within the hour, not at the next Monday or Thursday run.

## Acceptance criteria
<!-- Testable statements. G02 fails the spec if any is missing or untestable. -->
- [ ] A report whose title verdict is FAIL with at least one ✗ check line produces one `new` email; the same failures with different ages ("30 min ago", "12.0 h ago", "3.5 d ago") produce no further email within 24 h and one `reminder` after it (scripts/ops/pitwall-alert.test.js)
- [ ] A different set of failing checks while one is outstanding sends a `changed` email at once and keeps the first-reported time
- [ ] An OK or WARN report after an alert sends one `cleared` email and resets the state; an unreadable/empty report never counts as cleared
- [ ] ✗ lines inside the model-written `## Triage` section never start or stop an alert
- [ ] With no login file (ALERT_TO / SMTP_USER / SMTP_PASS) the script exits 5, writes to stderr and syslog (`journalctl -t pitwall-alert`) and does not advance its state; a refused send exits 6 and does not advance it either
- [ ] The alert step never changes the check's exit code; `PW_CHECK_QUIET=1` files no report and logs one line on an OK run
- [ ] Replaying the real 2026-11-05 → 11-12 reports gives: nothing, `new` at 11-08 19:33, nothing, nothing, `reminder` at 11-12
