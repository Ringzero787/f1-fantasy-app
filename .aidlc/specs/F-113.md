# F-113 — UC: an invite link opens the app, and the host it points at exists

Created: 2026-10-08 · Merged 2026-10-08 (PR #196) · Status: implemented · Reported from the field by the owner.

## What was reported
> "the email notification opened up undercut.humannpc.com not the mobile app"

## What it actually was
**`undercut.humannpc.com` does not exist.** `Status 3` (NXDOMAIN) from Cloudflare's own resolver,
while `humannpc.com` and `pitwall.humannpc.com` both resolve — so the zone is live and this
subdomain has simply never been created.

The invite email sends people to `https://undercut.humannpc.com/join?code=…`. The page never
loads, so the `theundercut://join/<CODE>` redirect inside `public/join.html` never runs, and the
browser sits on the address it failed to reach. From the outside that reads exactly as "it opened
the website instead of the app".

**The app side was never broken.** `extractInviteCode` in `app/_layout.tsx` already matches both
`theundercut://join/CODE` and `https://…/join?code=CODE`, and routes to the league join form.

### It is used in seven places, all dead
| where | what breaks |
|---|---|
| `app.config.js` `privacyPolicyUrl` | the URL **filed with all three stores** — Play rejected Track Limits for exactly a 404 privacy policy once |
| `src/simple/grid/GridLeagueManager.tsx` | the share-your-team link |
| `app/(tabs)/leagues/[id]/index.tsx` | the share message's join URL |
| `functions/src/invites/sendInviteEmail.ts` | the invite email |
| `functions/src/notifications/incompleteTeamAlerts.ts` | "Open Undercut" in alert emails |
| `app/(tabs)/profile.tsx` (×2) | privacy and terms |

The same content is live at `https://f1-app-18077.web.app/join` — fetched and confirmed serving
the real page.

## The decision
**Owner's call, 2026-10-08: create the subdomain rather than repoint the code.** No code change
for any of the seven, and the privacy URL already filed with Apple, Google and Amazon stays
correct — repointing would have meant re-filing it in three consoles. **This feature is inert
until that DNS exists.**

Owner steps: Firebase Console → Hosting → Add custom domain → `undercut.humannpc.com`, then put
the records it gives you into Cloudflare. Firebase issues the certificate itself.

## And the second half: the link should open the app directly
Even with the host alive, `public/join.html` relies on `window.location.href = 'theundercut://…'`,
which email clients and in-app webviews routinely block without a user gesture. So the owner also
asked for real **App Links / Universal Links**, which make the https URL open the app with no
landing page in the middle. The page stays as the fallback for desktop and for people without the
app.

### Built
- **`app.config.js`** — `ios.associatedDomains: ["applinks:undercut.humannpc.com"]`, and an
  Android `intentFilters` entry with `autoVerify: true` for `https://undercut.humannpc.com/join*`.
- **`public/.well-known/apple-app-site-association`** — `MWVD9BU5VW.com.undercut.app`, `/join`
  and `/join*`.
- **`public/.well-known/assetlinks.json`** — `com.undercut.app` with two fingerprints: the Play
  App signing certificate (what Play installs are signed with) and the upload key (the Amazon APK
  and direct installs).
- **`firebase.json`** — both files served as `application/json`. The Apple one has no extension,
  so Hosting would otherwise guess `application/octet-stream` and Apple would reject it.
- **`scripts/release/applinks.test.js`** — seven cases tying the pieces together, because every
  failure mode here is silent: Android quietly opens Chrome and iOS quietly opens Safari, which
  looks identical to the bug being fixed. It asserts the email host and the claimed host are the
  same string, the appID team prefix matches the archive script, the package matches
  `android.package`, the Apple and Android path lists are the same two paths, the Play signing
  certificate is listed, Track Limits' delegation is still there, Hosting would really upload both
  files, every fingerprint is a real uppercase colon-separated SHA-256, and both Content-Types are
  set. Each new case was checked against the state it guards and fails there.

## Two prerequisites — both now satisfied
1. **The Play App signing certificate is in `assetlinks.json`.** Play re-signs every upload with
   its own key, so our upload key (`70:EC:4C:…:CF:E7`) is correct only for the Amazon APK and
   direct installs; until the Play certificate was listed, Android App Links would not have
   verified for anyone who installed from Play, which is nearly everyone. It did **not** need the
   Play Console: `androidpublisher` v3 reports it. On 2026-10-08,
   `applications/com.undercut.app/generatedApks/69` returned
   `certificateSha256Hash = 3D:2B:59:DC:…:26:4F`, identical for versionCodes 67, 68 and 69, and
   downloading that generated APK and running `apksigner verify --print-certs` on it confirmed the
   same SHA-256 together with SHA-1 `45e235603ba3eb610c4d3e3116da61150ae45a5a` — the fingerprint
   already registered on the Firebase Android app, which is what identifies it as the Play key
   rather than the upload key. Both fingerprints are now listed, Play first.
   `applinks.test.js` asserts the Play one is present instead of merely warning.
2. **Associated Domains is enabled on the `com.undercut.app` App ID** and the profile regenerated.
   Expo's prebuild writes the entitlement; a profile without the capability makes **the next iOS
   archive fail to sign**, which is the one change here that can break a build rather than merely
   not work. The regenerated profile (`fe08ac16-b61e-4cc5-8294-278b50b3e6b7`, created
   2026-10-08, expires 2027-03-23) carries `com.apple.developer.associated-domains = *`, and it is
   installed on the Mac Mini. The March profile of the **same name** (`b829fe08-…`), which has no
   such entitlement, was moved to `~/old-provisioning-profiles/` — `uc-ios-archive.sh` signs
   manually by profile *name* with no `-allowProvisioningUpdates`, so leaving two profiles called
   "Undercut AppStore Distribution" installed would have made the choice a coin flip.

## Acceptance criteria
- [ ] **The invite host exists as a name.** `undercut.humannpc.com` resolves and serves Firebase
      Hosting. *Not met yet — the subdomain is still NXDOMAIN; this is the owner step everything
      below waits on.* Until it resolves, both platforms fall back to a browser, which is the
      reported behaviour.
- [x] **Android claims only the paths the app understands.** Two exact `path` entries, `/join` and
      `/join.html`, matching `extractInviteCode` in `app/_layout.tsx`; no `pathPrefix`, which would
      also claim `/join-pro` and every other string starting with those five characters.
- [x] **iOS claims the same two paths**, and the AASA `appIDs` team prefix is read from
      `scripts/release/mac/uc-ios-archive.sh` by the test rather than written twice.
- [x] **`assetlinks.json` carries the Play App signing certificate**, not only the upload key —
      otherwise verification fails for everyone who installed from Play. Derived from
      `androidpublisher` and confirmed with `apksigner`; see the prerequisites section.
- [x] **Track Limits keeps its delegation.** This Hosting site is shared: with no static file at
      that path Hosting auto-generates one, and on 2026-10-08 the generated file delegated to
      `com.tracklimits.app` alone. A static file shadows it, so this one carries both apps and a
      test refuses to let the Track Limits entry be dropped.
- [x] **Both files are actually uploaded.** `firebase.json`'s `ignore` contains `**/.*`; a test
      makes the same `glob` call `firebase-tools`' `listFiles` makes and asserts both appear, so
      nobody re-solves this with the rewrite F-091 used.
- [x] **Both are served as `application/json`.** The Apple file has no extension and Hosting would
      otherwise guess `application/octet-stream`, which Apple rejects.
- [x] **The iOS entitlement does not break the next archive.** Associated Domains is enabled on the
      App ID and the regenerated profile is installed on the Mac Mini; see the prerequisites.
- [ ] **Verified on a device.** `adb shell pm get-app-links com.undercut.app` shows `verified`, and
      an invite email opens the app. Cannot be done until the host resolves and hosting is deployed.

## Targets
- web (Firebase Hosting: the two association files and their headers)
- android, ios (native config only — `associatedDomains`, `intentFilters`; takes effect in 2.5.1)
- amazon: no App Links. Fire OS has no Play Services and the Amazon build is signed with the upload
  key, which is listed, but nothing verifies there — those installs keep the `join.html` redirect.

## Data
No collections, no schema, no personal data read or written. The invite code already travelled in
the email link; this changes only which application opens it. The two new files are public by
design and by specification — `assetlinks.json` must publish signing-certificate fingerprints and
the AASA must publish the Apple Team ID and bundle id, which is how the association is proved.
Neither is a secret and both are already committed elsewhere in the repo.

## Out of scope
- A Hosting site of its own for `undercut.humannpc.com`. That is the clean answer to the shared-site
  problem above and should be done once the domain exists; the union is the interim.
- `inviteCode` is still client-chosen and `joinLeague` resolves it with `limit(1)`, so a duplicate
  code captures someone else's joiners. Unchanged here, and unrelated to which app opens the link.
- `privacyPolicyUrl` in `app.config.js` still points at the same host and is filed with the stores;
  it starts working when the host does.

## Still open
- The app build. `associatedDomains` and `intentFilters` are native config, so they take effect
  only in 2.5.1 — they do nothing for anything already installed.
- Verification cannot be checked from here: both association files have to be live on the real
  host first. Once they are, `adb shell pm get-app-links com.undercut.app` on a device shows
  whether Android verified, and Apple's CDN caches the AASA, so allow time after a change.
- `public/join.html` keeps its automatic redirect. It is unreliable, which is the whole reason for
  App Links, but it is the only thing that helps a build predating 2.5.1. Note what it falls back
  to: `theundercut://join/<CODE>`, a custom scheme any installed Android app may claim — the same
  vector F-091 removed from the Amazon auth flow. App Links is what retires it, for 2.5.1 onward.
- **Before the hosting deploy, prove the shadowing on a preview channel.** `firebase
  hosting:channel:deploy` and then `curl` the channel's `/.well-known/assetlinks.json`: it should
  return both packages. That is the one claim here taken from documented behaviour rather than
  measured — that a static file overrides Hosting's auto-generated association file. If it turns
  out not to shadow, the Track Limits entry is harmless surplus rather than load-bearing.
