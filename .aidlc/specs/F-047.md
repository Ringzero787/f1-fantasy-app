# F-047 — TL: server-driven config, economy values and copy

Created: 2026-09-17 · Status: planned

## Goal

Changing basic game logic currently requires an app build, Play review and propagation. The 0.1.44 release showed the cost precisely: the stake-scaled win bonus (F-043) was a Cloud Functions change and was live in minutes, applying to Azerbaijan immediately — but the one sentence describing it to players was a hardcoded string in `src/components/tl/atoms.tsx`, so it needed a full build and will not reach most players before the race. Same feature, two latencies, and the slow half was a string.

The delivery mechanism already exists and is inert: `tl_config/app` is world-readable in production (verified 2026-09-17) and `AppConfigGate` has been mounted app-wide since 0.1.19, but the document has never been created. This feature creates that document and then moves the values and copy that currently force builds behind it, so they become changeable from the server.

This is a **delivery mechanism**, not new economy rules. The economy itself stays server-authoritative where it already lives — F-006 (garage cash economy) and F-007 (store and packs) are unchanged, and settlement math stays in `settleWeekend.ts`. What changes is that the client stops holding its own copies of those numbers.

## Acceptance criteria
- [ ] `tl_config/app` exists in production, created through an `aidlc op` with a recorded dry-run, and the app behaves identically before and after (kill-switch unset, notice disabled).
- [ ] `setAppConfig.js` dry-runs by default, applies only with `--write`, and prints every leaf change as `path: from → to`.
- [ ] `setAppConfig.js` refuses to write a `minSupportedVersionCode` above the shipped versionCode unless `--allow-block` is passed, so a mistyped floor cannot brick every live player.
- [ ] The client reads starting cash and roll starting cash from config, falling back to the current bundled constants when the doc is missing or the field is absent.
- [ ] The client reads cosmetic pack prices from config, falling back to `cosmeticsCatalog.ts`; the displayed price always matches what `tlBuyCosmeticPack` charges.
- [ ] A `copy` map in the config can override player-facing rules strings (at minimum the prediction-pill explainer and the onboarding bankroll text), falling back to the bundled English when absent.
- [ ] At least one real surface reads a flag through `appConfigFlag`, so the feature-flag channel is proven rather than theoretical.
- [ ] Every new field is optional and the app is fully functional with `tl_config/app` deleted — the gate fails open, verified by launching with the doc absent.
- [ ] No secret or player data is ever written to `tl_config/app` (it is world-readable).

## Targets
- android
- ios

## Data
No user data. `tl_config/app` is operator-authored configuration, world-readable by design (`firestore.rules`: `allow read: if true`, admin-write-only). It must never contain secrets, credentials or anything player-specific.

## Performance budget
No change to cold start. The config is a single document read on launch, already cached 5 minutes with `retry: 0`, and the gate renders children while it loads.

## Out of scope
- Changing any economy value. This makes existing numbers remotely settable; it does not retune them.
- Moving settlement math out of `settleWeekend.ts` — it is already server-side and should stay there.
- Localisation. The `copy` map is an override channel, not a translation system.
- Undercut. This is Track Limits only; the same treatment for UC is a separate feature.
- Over-the-air JS updates. This is config and copy, not code delivery.
