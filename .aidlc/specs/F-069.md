# F-069 — UC: Pit Wall analytics data pipeline

Created: 2026-09-19 · Status: planned

## Goal
Undercut (root app). The portal needs far more than the results the app ingests today (`functions/src/ingestion/openf1Client.ts` pulls sessions, results, drivers and laps). This feature builds the daily data layer every report reads, as precomputed documents so pages stay fast and cheap.

## Acceptance criteria
- [ ] **Timing data is free-only (ADR-001).** The timing source is non-commercial, so nothing derived from it is ever placed behind the pass: timing-derived payloads live in `pw_public_timing` (readable by any signed-in user) and no pass-gated payload may read from them; a unit test on the payload builders enforces the separation. The source sits behind one adapter so it can be swapped, a `config/app.pitwall.timingFrames` switch hides those frames without a deploy, raw timing data is never redistributed, and the owner's permission request to the provider is tracked in ADR-001.
- [ ] Runs on the forge worker (`workers/pitwall/`, systemd, pull-based `pw_jobs` queue with transactional leases, no inbound ports) from a dedicated deploy checkout `/data/pitwall-worker` that only the `pitwall-worker-deploy` op updates; never from a development checkout. A Cloud Run Job built from the same code is the backup: a Cloud Scheduler watchdog starts it only when due jobs exist and forge's heartbeat is stale, and the lease guarantees a job is never processed twice. Design in `docs/design/pitwall/ARCHITECTURE.md` section 6.
- [ ] Scheduled ingest: daily at 06:00 UTC plus 30 minutes after each session ends. Pulls laps, stints/compounds, pit stops, weather, race control (flags, safety cars) and grid/classification; history backfilled to 2023 through an `aidlc op`.
- [ ] Writes precomputed, versioned analytics documents: per driver-round, constructor-round, circuit, and season rollups (form, teammate deltas, quali vs race pace, stint degradation slopes, pit stop medians, positions gained, DNF causes, wet/dry splits, circuit-type splits).
- [ ] Fantasy-side rollups from our own data: price history, points per $, ownership and ace-weighted effective ownership per league, team value over time.
- [ ] Power-unit component usage and penalty tracker populated from official decision documents (manual admin entry acceptable in v1).
- [ ] Each run writes a run record (counts, gaps, duration); a failed or partial run alerts the admin and the portal shows "data as of" on every page.
- [ ] Unit tests cover each aggregate against a fixture weekend; unmapped drivers surface as warnings (same pattern as the existing unmapped-driver warning).

## Targets
- forge worker (GCP Cloud Run backup)
- firebase (functions, rules)

## Data
Public sporting data and our own game data. No new personal data.

## Performance budget
Daily run < 9 minutes on forge; session run < 5 minutes; backup runner cold start to first claimed job < 3 minutes.

## Out of scope
- Car telemetry traces (speed/throttle/brake) and any live session mirror.
